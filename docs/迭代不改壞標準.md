# 迭代不改壞標準（RTS 實驗線版）

業主 2026-10-10 在另外兩條線定的總原則：「不管迭代玩法還是美術，都不准迭代壞」。本線照同一個精神，換成本線的工具。**每一步都要能證明「沒變壞」；證明不了就停，交給業主。**

來源：`GlimmerTown-lab/docs/迭代不改壞標準.md`（2D 實驗線版）與 `GlimmerTown/docs/迭代不改壞標準.md`（主線版）。像素指紋、風格分數、四季檢查那些本線沒有的工具拿掉了。

## 1. 模擬

- 黃金雜湊 `tools/golden.json` 是模擬沒變的證明。沒改模擬的卡，雜湊一位都不准動。
- 改了模擬：卡頭 `sim=yes`、`golden=舊→新`，卡面寫為什麼變、變了什麼（例如「坦克裝填 60→50 tick」）。
- Node 與 Chrome 必須算出同一個雜湊；從指令紀錄重播要等於直接跑；中途深拷貝接著跑要等於直接跑。
- 會改世界的事都在 `step()` 裡；渲染不准改世界、不准用模擬的亂數。

## 2. 畫面

- 每張改畫面的卡，看 CI 附件 `shots-<sha>` 的四張樣張（桌機、手機，開局與 30 秒後），在卡面寫看到了什麼。
- 新效果要有逃生閥（`?noR<號>=1` 或既有閥），閥關時模擬雜湊不變。
- 全局觀感（畫風、後製、光、鏡頭）等業主看圖。

## 3. 指令與存檔

- 指令格式只加可選欄位；舊的指令紀錄要能照樣重播。做不到就標「等業主」。
- 本機存檔鍵名 `gtrts.v1.` 開頭；格式要改就加版本號，舊檔要能讀，絕不讓讀檔報錯。

## 4. 量測

- 要動效能先量，用最簡單的新舊交錯對比確認是真問題。
- 同一個問題的診斷卡最多連開 2 張，再來交業主。
- 牆鐘毫秒只記錄、不當門檻（共用的 CI 機器會抖）；門檻用繪製呼叫、三角形、步數這種數得出來的東西。

## 5. 守衛

- 每條新守衛都要故意弄壞一次，確認第一個紅燈落在它身上；卡面記下怎麼弄壞、紅在哪。
- 不拿受測的東西當標準答案。

## 6. 停手

- 同一件事試 2 次沒進展就停，交業主。
- 不准重跑 CI 賭綠；只有安裝、下載這類環境步驟失敗可以重跑一次。
- `main` 紅了：誰合的誰開純撤回 PR，不在 `main` 上疊修補賭綠。

## 7. 誠實

- 沒跑過的不寫「通過」，失敗照實寫。
- 「沒做成的事」不准空著，也不准美化。

## 8. 自檢清單（PR 轉 ready 之前逐條打勾，寫在卡面）

1. [ ] 卡面先推（分支第一個提交只有卡），驗收條件沒改過。
2. [ ] `npm run check` 在本機全綠；或寫明哪一步沒在本機跑、靠 CI。
3. [ ] 改了模擬：卡頭 `sim=yes`、`golden=舊→新`、卡面寫原因。沒改模擬：黃金雜湊不變。
4. [ ] 新效果有逃生閥，閥關時雜湊不變。
5. [ ] 手機預算沒超（煙霧測試會量）。
6. [ ] 新守衛故意弄壞過一次，紅在它身上。
7. [ ] 看過 CI 樣張，卡面寫了看到什麼。
8. [ ] 沒跑過的沒寫「通過」；沒做成的事照實寫。
