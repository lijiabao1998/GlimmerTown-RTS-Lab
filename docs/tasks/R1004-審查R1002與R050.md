## 為什麼做這張

R1002、R050、R1003 合併時子代理的週用量用完了，設計和審查都是我一個人做的（三張卡面「沒做成的事」第一條）。這一輪用量夠，補一次獨立審查。

## 審查怎麼做的

一個工作流（2026-11-21）：五個審查員各看一塊——R1002 模擬、R1002 介面與畫面與守衛、R050 模擬、R050 介面與畫面加 R1003 的守衛、三張卡和舊系統的交互（運輸、空襲、存檔、重播、對戰、電腦）。每個審查員找到的，再交給一個只負責反駁的核對員：讀程式、在隔離副本裡寫小腳本重現，重現不了就判「不是」。審查員和核對員都看不到我的結論，只拿到程式和卡面。

結果：19 條，核對員確認 18 條（其中兩對是不同審查員找到的同一件事，合起來 16 件），1 條判不是（潰退的工兵倒數照跑：R1002 卡面寫「倒數跟裝填一樣」，步槍裝填潰退時也照跑，是照卡面做的）。

## 不改什麼

- 沒有 `tech` 的局，模擬一行都不變（1、9 都只在 `construct50`、`why50` 裡）；黃金雜湊不變。
- **帶 `tech` 的舊紀錄**：如果那一局有人在別人的路上放了工地、或放在泥地上，重播會不一樣（那正是要修的行為）；其他的照舊。R050 上線一天多，卡面寫清楚。
- R1002、R050 的數字不改；介面只改審查指出的那幾條路由、模式、更新時機。

## 驗收（動手前寫）

1. `tests/review1004.mjs`（新，Node）：
   - `repath`：步兵、坦克、載著人的卡車、要架起來的反戰車砲，各自拿著穿過某一格的移動指令，走到一半時在那裡放工地：沒有人站進工地；車輛在 300 步內到達（或停在最近走得到的格）、指令變回待命；卡車放下人；砲架好開火（敵方坦克在射程內）。路不經過工地的單位，路一格都不變。
   - `mud`：萊伊上方那一方指揮部旁邊踩到泥的 2×2，`why50` 回「泥地不能蓋」，`construct` 不接；同一個位置往旁邊挪到不踩泥的照樣接。
   - `notech`：沒有 tech 的局（萊伊、鄉間 64 各一局，各 2,000 步）雜湊跟 main `407c030` 一樣（寫死）。
2. 路由（同一支，`route` 群）：選工兵加步兵加坦克，點躲在碉堡裡、看得到的敵方步兵：工兵收到對碉堡那一格的射擊指令，步兵、坦克收到攻擊指令；點空地上的敵人照舊全部攻擊。選工兵加坦克點自己的工地：只有工兵收到射擊指令；點自己蓋好的兵營：坦克也不收。點別人的房子照舊。
3. 模式：先武裝空中再按兵營 → 空中鍵沒武裝；先按兵營再武裝空中 → 建造沒武裝。點地圖只會走當下那一個模式。
4. 閥：`?noR091=1` 新開的局 eco 不帶 `sw`；`?noR1002=1` 照舊送 `sw`＝1；兩個都開送 2。
5. 畫面（Node 的真 BattleView）：工地出現時記的階段＝沒有屋頂；工地在血 2 時被打成瓦礫：不出屋頂碎片、不震鏡頭，沉下去的是沒有屋頂的那一份。工地掉到七成以下再蓋好：那一棟沒有還在燒、還在冒煙的；蓋到一半重建畫面再蓋好，也沒有。
6. 介面更新（瀏覽器，`tech50-browser` 擴充）：暫停中按「兵營」，鍵馬上亮、提示列馬上換（不靠 `__rts.select` 刷新）；點放不下的地方，理由馬上出來；按 Esc 取消；新開一局取消。
7. 守衛漏洞 10–15 各自補上，故意弄壞的時候紅。
8. 故意弄壞（隔離副本，手動跑一次、結果寫進施工紀錄）：不重新找路、重新找路不照 id 順序（換成倒序，雜湊要變）、不擋泥地、路由不分工兵、模式不互斥、工地記成完好、蓋好不收煙、不馬上更新、`sw1002` 不看 R091——每一處都要有守衛紅。
9. `npm run unit` 的內建段落、黃金雜湊；`engineer1002`、`tech50`、`support91`、`air93` 兩支負向照跑綠。
10. CI 全綠（含 `smoke`、瀏覽器分片）。
