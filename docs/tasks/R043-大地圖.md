## 為什麼做這張

R042 把地圖大小變成世界欄位，這張真的做一張大地圖。路線圖 R025「大地圖：64×64，合併網格、視錐裁切；手機預算不變」與業主這次的「更多坦克，更大地圖」是同一件事。

## 做什麼

1. **新地圖 `MAP_LARGE = 2`**（`src/sim/maps.ts` 或新檔 `src/sim/largeMap.ts`）：
   - 只在第 0 步由既有的 `map` 指令套用：`{ t: 'map', id: 2, vegetation?: 1 }`。
   - 套用時把世界換成 `n = 64`：重新配置地形、建築佔格、彈坑陣列；清掉 `createWorld` 給的 32×32 建築與單位，換成這張圖的。
   - 舊的 `map` 指令（id 0、1）一位都不變。
2. **地形**（程序生成，只用 `World.rng`，同種子同圖）：英格蘭東南鄉間。
   - 中間一座市鎮：十字大街、教堂廣場、沿街連棟。
   - 兩到三個小村、零散農舍。
   - 一條河斜穿地圖，至少兩座橋（路蓋過泥灘），田野、樹籬與小樹林（沿用 R116 的植被生成）。
   - 雙方出生角落（我方右下、敵方左上）各留 12×12 的空地。
3. **兵力**：「更多坦克」，雙方對稱。
   - 每方起手：中坦克 6、輕坦克 2、重坦克 2、榴彈砲 3、觀測員 2。
   - 單位 id 從 1 起連號。
4. **人口與補給**：大地圖有指揮部時，每方同時活著的上限 16 → 40。只在大地圖寫進 `w.eco`，有值才折進雜湊，舊局不變。
5. **效能**：
   - 模擬：單位變多後，`spotted()` 在開火階段同一步內會被同樣的參數問很多次。用一個只活在那一步的查表記住結果，結果逐位相同，黃金雜湊不變；不准跨 tick 留狀態。
   - 渲染：城鎮網格只建「鏡頭附近一塊」（視窗＋邊距）的建築；鏡頭移出一段距離或縮放變了才重建。陰影相機跟著那一塊走，不罩整張圖。32×32 的局視窗涵蓋整張圖，畫面逐像素相同。
   - 手機 412×860 開局繪製呼叫 ≤ 20、三角形 ≤ 80,000；戰鬥最熱時 ≤ 22／≤ 80,000。不調高預算。
6. **入口**：
   - 布陣時左上（「沙盒模式」旁邊）多一顆「地圖」鍵，在「萊伊 32×32」與「鄉間 64×64」之間切換。按下去回到那張圖的布陣第 0 步。
   - 網址 `?map=64` 直接開大地圖。`?noR043=1` 沒有這顆鍵，也不認 `?map=64`。
7. **其他**：
   - 小地圖照比例縮放、整張大地圖看得到；
   - 開戰命令條（R041）的地點寫「英格蘭東南鄉間（64×64）」；
   - 說明面板提一句大地圖；
   - README 逃生閥表加一列。

## 不改什麼

- 32×32 的萊伊與亂數村莊、舊指令紀錄、黃金雜湊、所有既有單位數值都不變。
- 不改畫風、後製、光的方向、鏡頭角度；不調高手機預算。
- 不加新兵種（那是 R044）。

## 驗收（動手前寫）

1. **Node 守衛 `tests/large-map.mjs`**：
   - 種子 0–49 的大地圖：`n === 64`；建築數在合理範圍（卡面記最小／最大）；出生角落 12×12 沒有建築；單位不站在建築上；每個單位都走得到每個敵人；河上至少兩座橋；雙方起手兵力照第 3 條。
   - 有指揮部（eco）時雙方指揮部都放得下，人口上限 40。
   - 電腦對手（普通）在大地圖上 60 秒內推進到地圖中線另一側。
   - 指令紀錄經 JSON 來回重播、600 步中途 `structuredClone` 接著跑，雜湊都相同。
   - 舊 `map` 指令（0、1）的世界雜湊與改之前相同。

3. **黃金雜湊 `eea1d59b` 不變**；既有守衛全綠。

   - 瀏覽器雜湊＝Node 重播；
   - 真觸控按「地圖」鍵切到大地圖、再切回萊伊；
   - `?noR043=1` 沒有鍵、`?map=64` 不生效、雜湊不變；
   - 樣張：大地圖開局（手機、桌機）、市鎮特寫、交戰特寫，卡面寫看到什麼。
5. CI 的 `smoke` 總閘綠。
