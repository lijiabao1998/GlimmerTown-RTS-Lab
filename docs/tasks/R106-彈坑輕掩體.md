# R106［待辦 6］彈坑輕掩體：炮火留下的落腳處
<!-- card: sim=yes; golden=2269decb→待測; valve=無; owner_ok= -->

## 為什麼做
砲彈改變地面，也應改變站位的價值。既有彈坑會拖慢移動，現在讓留在彈坑中的單位少受一些炮火傷害，形成速度與掩護的取捨。

## 做什麼
- 單位所在格已有任一深度彈坑時，投射物傷害按 75% 計算（原 100%），最後與既有裝甲倍率一起整數取整；兩方與各單位類型共用規則。
- 完好／空殼建築與碉堡的既有 50%／25% 掩護優先，不與彈坑疊乘；建築倒塌傷害仍按原規則，不吃彈坑減傷。
- 保留高爆彈先造成傷害、再形成彈坑的順序；製造第一個彈坑的那發不享受自己產生的掩護。
- 沿用現有彈坑地面圖像、深度與減速，不加視覺效果或指令欄位；README 解釋站位取捨。

## 不改什麼
不改敵方 AI、步兵專屬行為、單位數值、建築耐久／減傷、命中與散布、彈坑生成／減速、地圖、介面操作、渲染幾何、手機預算、依賴或受保護檔案。不帶入 R104 裝甲，也不實作 R024b 障礙物。

## 驗收（動手前寫）
1. 既有彈坑深度 1／2／3 都讓投射物傷害只吃 75%，空地 100%；對雙方與各單位類型一致，使用實際所在格與整數運算。
2. 普通建築 50%／碉堡 25% 掩護保持原值，不疊乘；瓦礫只有在該格另有彈坑時才提供輕掩護；倒塌傷害不因彈坑降低，建築本體傷害不變。
3. 直接射擊與高爆範圍傷害均遵守規則；第一發高爆彈不因新挖的坑自我減傷，後續命中才可利用留下的坑。
4. 移入或離開彈坑立即使用新位置的掩護，不新增持續狀態；既有彈坑深度上限、通行與減速不變。
5. 舊指令 JSON、相同種子重跑、中途 structuredClone 接續一致；已有世界無需遷移；Node／Chrome 黃金雜湊相同。
6. 新守衛逐組有故意弄壞且對應紅燈的證據；既有守衛不削弱。typecheck、unit、build、smoke 與 main 版 gpt-lane 結果逐項記錄，無法本機跑的誠實寫明；手機與戰鬥預算不提高，確認 CI 四張樣張未退化。
