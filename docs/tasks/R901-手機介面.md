# R901 手機直向：可收合介面與可靠觸控

<!-- card: sim=no; golden=無; valve=?noR901=1; owner_ok= -->

## 為什麼做

412×860 直向時，上方按鈕列和底下的建造／生產列蓋住一大塊地圖，手指又要把框選、雙指縮放、長按下指令分清楚。這張只補手機操作，不改戰鬥結果。

## 做什麼

- 直向窄螢幕（含 412×860）多三顆至少 44×44 的鍵：收起／展開上方按鈕、收起／展開建造列與生產列、開／關觸控框選。鍵留在 `env(safe-area-inset-*)` 安全區內。收起後那一塊改由地圖接收點擊。
- 框選打開時，單指拖曳沿用既有框選（超過 8 CSS 像素才算拖、只加存活我方、不平移、不下令）。關掉時單指拖曳仍是平移。雙指捏合仍只縮放、不補點。未開框選時，靜止長按 500 毫秒仍叫出既有砲擊選單，點選單才發一條既有 `fireAt`。
- 觸控時擋掉頁面自己的捏合與長按呼出，避免跟遊戲手勢搶。`?noR901=1` 不建這三顆鍵，框選開關也不存在；R109 的滑鼠框選與長按仍在。
- `tests/input-browser.mjs` 用真實觸控蓋過框選拖曳、雙指縮放、長按下指令；另用 Node 守衛鎖收合狀態與手勢分支。

## 不改什麼

不改 `src/sim`、黃金雜湊、相機數學（捏合仍呼叫既有 `zoomAt`／`zoomBy`）、`src/render/post.ts`、`src/sim/ai.ts`、`tools/`、繪製預算、npm 套件。不把預設單指拖曳改成框選。`main.ts`、`src/render/battle.ts` 不超過行數上限，也不調高上限。

## 驗收（動手前寫）

1. 412×860 直向看得到三顆至少 44×44、中心點得到自己的鍵（上方按鈕、建造／生產列、觸控框選）。樣式使用 `env(safe-area-inset-top/right/bottom/left)`。展開時這三顆不壓住既有工具列、小地圖、提示列、生產列或布陣列的按鈕。
2. 收起上方按鈕後 `#hud .btns` 不再擋點，原按鈕中心改點到地圖；收起下方列後 `#prodbar` 與 `#buildbar` 同樣讓出。再展開後按鈕回到至少 44×44 且點得到。桌面寬視窗與 `?noR901=1` 沒有這三顆鍵，舊版面不因本卡改位置。
3. 框選開著時，單指觸控拖曳超過 8 CSS 像素會畫出既有選框，把框內存活我方加進選取，鏡頭不平移、不發指令。框選關著時同一種拖曳仍平移。雙指拉開會改變縮放且不補一次點按、不發指令。未開框選時，單指靜止長按仍打開砲擊選單，點一顆選單鍵只發一條既有 `fireAt`。`?noR901=1` 沒有框選鍵，長按選單仍在。
4. 不改模擬與 `tools/golden.json`。新行為只靠 `?noR901=1` 關掉。DOM 不增加 WebGL 繪製呼叫。`src/main.ts` 與 `src/render/battle.ts` 行數不超過 `tools/hub-budget.json`，本卡不改那份上限。
5. `tests/input-browser.mjs` 在 412×860 觸控視窗蓋過第 3 條；Node 守衛蓋過收合狀態切換，以及觸控框選開／關與第二指取消。本機若 Chrome 受 socket 限制，瀏覽器守衛如實標未跑，不當通過。

## 施工紀錄

- 新檔 `src/ui/mobileChrome.ts`。直向且寬度 ≤480 才把 `#r901-chrome` 掛上：三顆 44px 鍵（具／產／框），位置用四邊 `env(safe-area-inset-*)`。預設展開。收起上方按鈕是 `body.r901-top-off` 把 `#hud .btns` 設成不顯示；收起建造／生產列是 `body.r901-bar-off`。寬視窗把節點拿掉，並清掉收合 class，所以框選不會留在桌面。框選只有「人在直向手機、而且這顆鍵按著」時，單指才走既有框選。
- 這三顆鍵用 `pointerup` 切換（移動超過 8 CSS 像素不算一次點）。拖完地圖後，有時等不到 `click`。`canvas` 在 `pointerup`／`pointercancel` 放開 pointer capture，下一點才打得到鍵。雙指 `touchmove` 與 `gesturestart`／`gesturechange` 擋掉瀏覽器自己的捏合；縮放仍呼叫既有 `zoomAt`／`zoomBy`。沒在 `pointerdown` 上 `preventDefault`。
- `src/ui/gestures.ts` 的 `touchBox()` 可選，沒給就是關。`src/main.ts` 只加三行接線（import、把 `touchBoxArmed` 交進去、`V.r901` 才 `initMobileChrome`）。`main.ts` 656 行，上限 673。`src/render/battle.ts` 1175 行，沒改。
- 閥是 `src/valves.ts` 的 `get r901()`。README 逃生閥對照加一列。`index.html` 加收合樣式、`overscroll-behavior`、canvas 不選字。不寫 `localStorage`／`sessionStorage`（同一瀏覽器裡 `fresh()` 會把收合狀態漏到下一局）。

## 驗收結果

- `node tests/mobile-ui.mjs` 通過：收合狀態、寬視窗不留 class、觸控框選開／關、8 像素內仍是點、第二指取消、滑鼠 Shift 框選不受影響、閥與行數。
- `node tests/input-browser.mjs` 通過（無頭 Chrome 156，約 47 秒）。正向：box、hold、routing、hint、cancel、layout、productionLayout、valve。八個負控仍紅在原來那句（box 紅在「四向把活著的我方加進選取」）。觸控斷言接在既有滑鼠框選之後，所以 box 負控不會先死在新句子。
- 同一輪還通過：`gestures`、`input-timing`（兩者含 `--mutations`）、`valves`、`readme`（54 個閥含 noR901）、`hub-budget`、`smoke-controls`、`audio-ui`、`tsc --noEmit`。
- `input-browser` 開頭對過 `tools/golden.json`，雜湊沒改。收合前後在同一鏡頭、同一選取下繪製呼叫相同，並且 ≤22 呼叫、≤80000 三角。`main.ts` 653→656（上限 673），`battle.ts` 1175 不變。

### 沒做成的事

- 沒在 Android 實機上試，只跑了無頭 Chrome 156。
- 安全區只確認樣式寫了四邊 `env(safe-area-inset-*)`。這台 Chrome 沒有非零的瀏海 inset。
- 收合不記檔。重新載入回到展開。
- 預設不收合。一收合，既有煙霧測試在 412×860 就點不到生產列和說明鍵。要讓地圖變大，得先點「具」或「產」。
