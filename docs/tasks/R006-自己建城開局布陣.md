**跟 GPT 線的關係**：方向檔待辦 4–14 沒有「玩家自己蓋」；待辦 5（建築材質）、12（樹籬）改的是地圖上的東西，不是玩家布陣。本卡只新增指令與布陣介面，不改既有建築的數值。

## 為什麼做這張

業主的核心玩法第一句是「自己建」，現在玩家完全不能建：地圖是種子生成的，開局就直接打。房子在這個遊戲裡是掩體、是擋視線的牆（R100）、也是會被轟爛的東西——讓玩家在開戰前親手把房子放在自己想要的位置，「對轟」才有自己的戰術。

## 做什麼

1. **模擬：新指令 `build`**（只加不改）：`{ t: 'build', side, kind, x, z, rot? }`。只在第 0 步接受（開戰前布陣）；之後送來的一律不理。
   - 三種：農舍 1×1、1 層、建材 1；磚房 2×1、2 層、建材 2（`rot=1` 轉成 1×2）；穀倉 2×2、1 層、建材 3。血量照既有的 `bldMaxHp` 算。
   - 每方建材 8。
   - 只能蓋在自己的半場：我方 `x + z ≥ N + 2`、敵方 `x + z ≤ N − 4`（中間留一條無人帶）。
   - 不能蓋在路上、地圖外、活著的單位所在的格；跟其他建築至少隔一格（跟地圖生成的規矩相同）。
   - 蓋了之後，所有活著的單位仍要互相走得到（不能把路堵死）。
   - 玩家蓋的建築記下是哪一方蓋的；這個欄位只有玩家蓋的建築才有，只在有的時候折進世界雜湊（沒布陣的世界雜湊不變）。
2. **敵方布陣**：純函式 `enemyPlan(world)`，只看種子與地圖，用自己的亂數狀態（不動 `World.rng`、不改世界），在敵方半場用同一套規則挑位置擋住己方火砲與來路，用完建材為止。開戰時跟玩家的布陣一起寫進指令紀錄，重播照樣得到同一個結果。
3. **介面**：開頁先進「布陣」（停在第 0 步）：我方可蓋的半場在地面上染色；布陣列有「農舍 1／磚房 2／穀倉 3／轉向／復原／開戰」與剩餘建材；點地面放下（放下的房子直接用真的建築模型畫出來）；不能放時在提示列寫原因（不在我方半場、在路上、太靠近別的房子、會堵死通路、建材不夠、有單位站著）。按「開戰」：寫入我方與敵方的 `build` 指令（第 0 步），開始打。「↺」回到布陣。按鈕 ≥ 44 CSS 像素。
4. **逃生閥**：`?noR006=1`＝沒有布陣，開頁直接開打（R102 的流程）。
5. **守衛** `tests/build.mjs`；煙霧測試加真觸控布陣。

## 不改什麼

- 不改既有建築、地圖生成、單位數值、腳本戰鬥；黃金雜湊不變（`fe1c5774`）。
- 不改既有指令的格式；舊紀錄照樣重播。
- 不改畫風、後製、光、鏡頭；不調高手機預算；不加 npm 套件。

## 驗收（動手前寫）

1. `npm run check` 本機與 CI 全綠；黃金雜湊仍是 `fe1c5774`；Node＝Chrome。
2. `tests/build.mjs`：合法的布陣會出現正確大小、層數、血量的建築，建材照扣；以下每一種都被拒絕而且世界不變：第 0 步以後、對方半場、無人帶、路上、地圖外、壓在單位上、離別的建築不到一格、超過建材、不存在的種類、會堵死通路的位置（造一個真的會堵死的場景）。
3. `enemyPlan`：種子 0–199 都只回傳合法指令、用的建材 ≤ 8 且 ≥ 5、套用後兩方互相走得到；同一個種子兩次結果相同；呼叫前後世界雜湊相同（不動 `World.rng`）。
4. 決定性：含布陣的指令紀錄跑兩次相同、JSON 來回重播相同、中途 `structuredClone` 接著跑相同；不含布陣的舊紀錄雜湊跟 R102 相同。
5. 煙霧測試（手機 412×860，真的觸控事件）：開頁在布陣、停在第 0 步、開局繪製呼叫 ≤ 20 與三角形 ≤ 80,000；點我方半場的一格 → 布陣多一棟；點「開戰」按鈕 → 紀錄裡有第 0 步的 `build` 指令（我方與敵方），之後跑 100 步，瀏覽器雜湊等於 Node 重播；拍 `mobile-build.png`（放好房子、還沒開戰）。
6. `?noR006=1`：開頁直接開打（不停在第 0 步），既有的觸控測試照舊通過，雜湊不變。
7. 每條新守衛故意弄壞一次，第一個紅燈落在它身上（記在卡面）。
8. 看本機與 CI 樣張，卡面寫看到了什麼。
