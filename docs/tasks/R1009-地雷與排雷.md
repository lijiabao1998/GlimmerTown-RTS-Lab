## 為什麼做這張

- R050 卡面「沒做成的事」第 2 條：沙包、修橋、排雷。這張是排雷（排雷之前要先有人布雷，所以布雷也在這張）。
- 1940 年英國的海岸防禦裡有碉堡、鐵絲網、反戰車障礙和雷場。碉堡、鐵絲網場上已經有了（R024、R121），雷還沒有。
- 進攻的一方要工兵走在前面用刺刀、探針戳（能用的制式探雷器——波蘭式——是 1941–42 年冬天才設計出來的）。這是 R1002 工兵的第三件事：拆房子、剪網之外，戳雷、排雷。
- 在玩法上，雷是「看不見的鐵絲網」：擋車擋人，但只有布的人知道在哪裡。要破它，得先派工兵去戳。

## 做什麼

### 1. 兩種雷（不是新的單位，也不是新的建築；`UNIT_KINDS`、建築種類一個都不加）

一格雷＝那一格裡埋的一小片雷（遊戲的距離是壓過的，一格是幾十公尺這一級），不是一顆。

| | 反戰車雷（kind 1） | 反人員雷（kind 2） |
|---|---|---|
| 補給（每格） | 15 | 10 |
| 布一格（工兵·步，兩個工兵一半） | 120 | 80 |
| 排一格（每個工兵自己倒數，跟 R1002 爆破一樣） | 160 | 200 |
| 誰會把它弄響 | 敵方的車和砲（`radius` ＞ 0） | 敵方任何地面單位 |
| 炸到有裝甲的車（`armored`） | 60 | 0 |
| 炸到沒裝甲的車、砲 | 60 | 10 |
| 炸到徒步單位（`radius` ＝ 0） | 20 | 30 |

- 傷害再乘目標自己的承傷（`armor`，重坦克 70），**不吃任何掩護**（壕溝、彈坑、樹林都不算：雷在腳下）。不看穿甲率（雷打的是車底和履帶）。
- 換算：坦克（100）吃一顆反戰車雷剩 40、重坦克剩 118、輕坦克剩 10；裝甲車、卡車、榴彈砲、反戰車砲一顆就毀。步兵班（60）吃一顆反人員雷剩 30、工兵（40）剩 10、火焰噴射器（20）全滅。

### 2. 規則

#### 2.1 只在 `mine`＝1 的局

- `eco` 指令多一個選填旗標 `mine`（只認 1；其他值當成沒送）。要 `sw`＝2（有工兵）、不是喪屍防守才存成 `w.eco.mine = 1`。沙盒不收 `eco`，所以沒有。
- `main.ts` 送 `mine` 的條件＝**送 `sw`＝2 的同一個條件**再加 `V.r1009`（R1004 之後 `sw`＝2 要 `V.r1002 && V.r091`；生產列的「地雷」組用同一個條件）。不然 `?noR091=1` 時會送 `mine`、出「地雷」組，但模擬沒有 `sw`＝2、存不下 `mine`，那一組永遠「本局未開放」。施工時在 `ui/mines1009.ts` 寫一支 `on1009(V)` 給兩處共用。
- `w.eco.mine` 進雜湊（記號 `0x4d49`，只在有時折）。
- 布陣（第 0 步）不能布雷；雷只能由工兵在開打之後布（布陣時的預置雷場寫在「沒做成的事」）。

#### 2.2 布雷指令 `{ t: 'mine', side, ids, kind, x, z, rot?, len? }`

- 一條指令布一格或一條雷帶：`len` 1–3（沒寫＝1），`rot` 0＝從 (x, z) 往 +x 排、1＝往 +z 排（沒寫＝0）。
- 放得下才接，**整條一起接或一起不接**。放得下的條件（介面和模擬用同一支 `why1009`，照這個順序回原因）：
  1. `mine` 開著、不是喪屍防守、不是沙盒、還沒分勝負、不是第 0 步（布陣）、`side` 是 0 或 1 ——不然「本局未開放」；
  2. 這一方的指揮部還站著——「指揮部已毀」；
  3. `kind` 是 1 或 2、`len` 是 1–3 的整數、`rot` 是 0 或 1 ——「不能布這種」（`len`、`rot` 沒寫才當 1、0；寫了但型別不對一律不接）；
  4. 這一方的雷（布好的加還在布的）加上這一條不超過 24 格——「已經布滿 24 格」；
  5. 補給夠 `每格補給 × len`——「補給不足，還差 N」（沒給位置時照一格算）；
  6. （沒給位置時到這裡就回「可以」：生產列的按鍵用）
  7. `ids` 裡至少一個是這一方、活著、沒坐車、沒在潰退的工兵（R050 的 `builders50`；`ids` 不是陣列當成空的，同 `construct` 那一行的寫法）——「先選工兵」；
  8. 每一格都在地圖裡、座標是整數——「超出地圖」；
  9. 每一格跟敵方指揮部佔地的八方向距離都大於 5（出生那一圈、集結點、排的第二三班集結點都在 5 格內）——「離敵方指揮部太近」。看的是 `eco.hq[對方]` 那一棟的佔地，不管它還站不站著；`eco.hq[對方]` 是 0（放不下指揮部的圖）就不看這一條；
  10. 沒有一格是泥地（河、運河、潮間帶）——「不能布在水裡」；路和橋可以；
  11. 每一格：不是建築或瓦礫（`occ`）、沒有鐵絲網（剪斷的也算，同 `why50`）、沒有壕溝、沒有自己的雷、沒有**這一方知道的**敵方雷、上面沒有活著（沒坐車、沒被拖著）的單位——「擋到了」。
- 同一格每一方最多一格雷。這一方**不知道**的敵方雷不擋（不然「擋到了」就把它洩漏出去）：兩方的雷可以疊在同一格。
- 接了：扣補給；`w.mines` 沒有就建（`{ version: 1, cells: [] }`，第一次布才建，之後不刪）；照雷帶的順序每格加一筆 `{ side, kind, x, z, left: 布一格的工作量, seen: 0 }`；`ids` 裡能布的工兵拿到射擊指令（`ORD_FIRE_AT`，目標＝第一格，已經挨著就不給路，不然 `findPath` 走向那一格）。不出事件（畫面自己比對，見 6）。

#### 2.3 布

- 工兵拿著射擊指令、目標那一格有自己還沒布好的雷（`left` ＞ 0）、那一格沒有還站著的建築或還沒壞的鐵絲網：沒在走、跟那一格八方向距離 ≤ 1（R1002 的「挨著」），每一步 `left` 減 1（每個工兵各減 1，兩個工兵一半時間）。工兵不會走進那一格（R1002 的「到了沒」：挨著就停）。
- `left` 到 0＝布好了（開始會響）。布好那一步，**敵方看得到那一格**（`spotted(w, 對方, center(x), center(z))`，R100 的視線規則，偵察機也算）就算被看到：叫 `reveal1009`（見 2.4），跟戳到一樣會「看到就停」。在敵人眼前布雷，敵人就知道。
- 布好之後，工兵找下一格：自己的、還沒布好的、離剛布好那一格八方向 ≤ 2 的雷，照 `w.mines` 的順序第一筆；有就換目標走過去，沒有就回待命。一條雷帶一個工兵會從頭布到尾。
- **兩個工兵布同一格**：同一步裡先輪到的那個把 `left` 減到 0，後輪到的那個看到「目標是自己剛布好的雷」也照上一條找下一格（不是回待命），兩個人一起往下布。不寫這一條，第二個工兵會因為目標沒了而回待命，雷帶只剩一個人在布。
- 潰退的工兵不布（R052：`canFire` 擋在前面）；被壓制不變慢（同 R050 蓋房子）。
- 布到一半走開（收到別的指令）就停在那裡，已經做的保留；工兵點那一格（射擊指令）接著布。補給不退。

#### 2.4 戳到（敵方知道了）

每一步、全部單位移動和推擠之後（`mines1009Step` 的前半）：

- 每一格對方還不知道的雷（`seen`＝0，布好的、還在布的都算），對方有工兵（活著、沒坐車）站在它八方向 1 格以內（含站在上面）：`reveal1009`。只有工兵戳得到；步兵、坦克走過旁邊不會發現。不看視線、不看煙（是用手戳的）。
- **`reveal1009(w, m)`：`seen` 從 0 變 1 的唯一入口**（2.3 布好時被看到、2.4 戳到、2.5 第 7 點炸了帶出旁邊的，三處都叫它）。它做兩件事：`seen`＝1；**看到就停**——看到的那一方所有活著、沒坐車、沒在潰退的單位，剩下的路（`path[pathIdx…]`）會走進那一格的，全部停下（回待命、路清掉）。路不經過那一格的照走。
- **工兵不走進知道的雷**：每一步（同一段），這一方的工兵（活著、沒坐車、沒在潰退）下一個路點（`path[pathIdx]`）是這一方知道的敵方雷那一格、而且那一格不是它射擊指令的目標：停下（回待命、路清掉）。原因：尋路不繞開雷，工兵從雷帶的一端去排第二格，A* 的直線會先穿過第一格——排雷的人自己踩上去。射擊指令的目標那一格不用擋：挨著就停（`reach1002`），本來就不會走進去。其他兵種不套用（見「沒做成的事」1 與審查意見）。
- 工兵是一格一格走的（在路上每步最多 12 個位置單位，一格 256），走進雷那一格之前一定先站到旁邊那一格，所以走路經過的工兵一定先戳到、先停下，不會自己踩上去。

#### 2.5 觸雷

同一步、戳到之後（`mines1009Step` 的後半），照 `w.mines` 的順序看每一格布好的雷（`left`＝0）：

- 那一格裡站著的、id 最小的、會把它弄響的敵方單位（活著、沒坐車、沒被拖著：反戰車雷要 `radius` ＞ 0，反人員雷不限）——有就炸：
  1. 那一格裡每一個敵方單位（活著、沒坐車、沒被拖著）照 1 的表扣血：呼叫 `damageUnit(w, t, 傷害, false)`（`allowGroundCover`＝false，承傷照乘）；
  2. 弄響它的那一個（還活著的話）停下（回待命、路清掉）；
  3. 那一格沒有還站著的建築時彈坑深度加 1（最多 3，同高爆落地）；
  4. 出一個高爆落地事件（`{ e: 'impact', kind: SHELL_HE, …, bld: 0, r: 128 }`：迫擊砲那一級的畫面和聲音；同 R1002 的爆破）；
  5. 士氣規則開著時，照高爆落地壓制：`suppressBlast(w, 那一格中心, SUB, 徒步的那一欄傷害)`（兩格內敵我都壓）；
  6. 這一格雷拿掉（一格只炸一次）；
  7. 布雷那一方在它八方向 1 格以內、對方還不知道的雷，照 `w.mines` 的順序各叫一次 `reveal1009`（看到就停）。炸了一顆，整隊就會停下來找旁邊的。
- 自己的雷不會被自己人弄響（遊戲取捨：自己人知道通路在哪；真實會，寫在出處）。還在布的雷不會響。
- 坐在車上的人照 R092：車被炸毀時由 `carry92` 照原本的規矩放下、扣血（`mines1009Step` 在 `carry92` 之前）。被拖著的砲不另外算（拖它的車會先響）。

#### 2.6 排雷

- **怎麼下**：工兵對那一格的射擊指令（跟 R1002 剪網一樣：點地上那一格）。`applyCommand` 的 `fireAt` 對工兵本來就走 `fireAt1002`；它最前面多一行先問 `fireAt1009`：
  - 那一格有還站著的建築或還沒壞的鐵絲網：不是雷的事，照 R1002；
  - 有自己還沒布好的雷：接著布（2.3）；
  - 有**這個工兵那一方知道的**敵方雷（還沒布好的也算）：排——射擊指令、目標那一格、倒數保持至少「排一格」那麼多步（`cooldown = max(cooldown, 160 或 200)`）、走到挨著；
  - 都不是：照 R1002（空地＝不接、指令不變）。**對方不知道的雷，下了跟對空地下一模一樣**，不洩漏。
- **怎麼排**：挨著、沒在走，倒數才往下數（`fireUnit` 原本就每步減 `cooldown`，被壓制時照 R052 變慢）；還沒挨著或還在走，倒數撐在至少那麼多。倒數到 0：那一格雷拿掉、工兵回待命。不會失手（不抽亂數）。
- 兩個工兵排同一格：各數各的，先數完的拿掉；另一個的目標沒了，下一步回待命。
- 自己布好的雷不能起出來（點了跟點空地一樣）。潰退的工兵不排。

#### 2.7 誰知道哪一格

`known1009(w, side, m)`：`m.side === side || m.seen === 1`。畫面、介面、以後的電腦都只能經過這一支看雷；`w.mines` 的原始清單只有模擬自己的規則碰。

#### 2.8 雷不管的事

- 雷不擋路、不擋視線、不擋射線；尋路不繞開（見「沒做成的事」1，也是這張最大的開放問題）。
- 砲彈、炸彈、火焰、爆破不會引爆雷；雷不會連鎖。
- 雷不算建築：不進 `blds`、`occ`，倒塌、駐守、勝負都跟它無關。

### 3. 存檔與雜湊的格式

- `World.mines?: { version: 1; cells: Mine1009[] }`，`Mine1009 = { side, kind, x, z, left, seen }`（全是整數；`left` 0＝布好了，＞0＝還差多少；`seen` 0／1＝對方知不知道）。
- 雜湊：在 `w.tech` 那一行下面加一行：`w.eco?.mine` 有才折（`0x4d49`），`w.mines` 有才折（`0x4d4c`、版本、筆數、每筆六個數）。沒有這兩樣的世界逐位不變。
- 存檔（`mineOk`，`worldCodec.ts` 一行接上）：`eco.mine` 只能沒有或 1；沒有 `eco.mine` 就不能有 `mines`；有 `eco.mine` 時 `eco.sw` 要是 2、不能是喪屍防守；`mines` 是物件（不是陣列、不是 null）、版本 1、`cells` 是陣列、最多 48 筆，順序原樣保存（雜湊、觸雷都照這個順序）；每筆六個整數，`side` 0／1、`kind` 1／2、`x`、`z` 在地圖裡（看 `r.n`）、`left` 在 0 到那一種的布雷工作量之間、`seen` 0／1；同一方同一格不重複；每一方不超過 24 格。

### 4. 閥

`?noR1009=1`：新開的局 `eco` 不帶 `mine`，生產列沒有「地雷」那一組。帶 `mine` 的紀錄、存檔照樣重播、照樣畫（模擬和畫面都不看閥）。

### 5. 介面
