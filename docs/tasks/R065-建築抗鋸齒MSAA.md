## 為什麼做這張

方向檔待辦 35「建築抗鋸齒」：GPT 的 R131／R134 做完建築細節，剩 MSAA 卡在受保護的 `src/render/post.ts`（渲染目標是後製私有的，GPT 改不到），卡住表 35 交給 Claude。業主 2026-10-27 說「全部做完吧」。

現在的畫法：場景先畫進一張半解析度的渲染目標（`pixelCss 2`），再用最近鄰放大到螢幕，加描邊與 12 階量化。渲染目標沒有多重取樣，房子的斜邊、屋脊、牆角在半解析度上就是硬鋸齒，放大後一階兩個 CSS 像素，手機上特別明顯。

## 做什麼

1. `post.ts`：`Style` 多一個 `msaa`（取樣數）；`Pipeline` 照它開渲染目標的多重取樣，取樣數不超過顯示卡的上限（`maxSamples`）；取樣數變了才重建渲染目標。深度照樣解析出來給描邊用。
2. 預設 4 倍；`?noR065=1` 回到 0（不取樣），畫面逐位等於原本。閥加在 `src/valves.ts`，`main.ts` 只在建 `style` 那一行接上。
3. **畫風不改**：解析度仍是 1/2（`pixelCss 2`）、描邊、12 階量化都照舊；只是邊緣那一格會是兩邊顏色混出來的中間色，不再是硬階梯。
4. 給業主看圖：同一個鏡頭、同一個世界，開／關各截一張（萊伊、96 圖、近看建築），放大對照。

## 不改什麼

- 模擬、黃金雜湊、單位與建築模型、光源、陰影、鏡頭都不動。
- 不改解析度（`?px=` 照舊）；不加 FXAA 之類的後製濾鏡。

## 驗收（動手前寫）

1. `npm run typecheck`、`npm run build` 過；黃金雜湊 `eea1d59b` 不變。
2. 守衛 `tests/msaa.mjs`（Node）：`Style` 預設 4、閥關時 0；`Pipeline` 照設定開取樣、不超過 `maxSamples`、取樣數變了才重建、大小變了取樣數不掉。故意弄壞：取樣數寫死 0、不看上限、換大小掉取樣，各紅在對應那一句。
3. 真 Chrome：開閥時渲染目標的取樣數是 4（或顯示卡上限）；`?noR065=1` 的畫面與改之前的程式逐位相同；開閥後房子邊緣有中間色（同一張圖，邊緣像素的顏色種類變多），描邊還在。
4. 既有瀏覽器守衛全綠（它們比的是同一頁裡開／關或前後兩次，取樣開著也要過）。
5. 截圖給業主：開／關對照，放大到看得出邊緣。
6. 全套 CI（unit 四份、chrome、`smoke` 總閘）綠。
