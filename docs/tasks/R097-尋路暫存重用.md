## 為什麼做這張

路線圖第 8 張（R090 更大的戰場）跑了設計工作流（三份方案＋裁判，2026-11-18）。裁判選了 128×128 的新地圖（地圖 5），並把一件事拆出來先做：

- **每一次尋路都配一整張圖的暫存**：`findPath` 每叫一次就新開四個跟地圖一樣大的陣列（每格擋不擋、走到這格花多少、從哪格來、做完沒），再全部填一遍。96 圖一次約 92 KB、128 圖約 164 KB；全選 47 個單位下一個移動指令，128 圖一次就丟出 7.7 MB 的垃圾，瀏覽器要停下來收。設計時的原型（陣列重用）在 3,200 對起點終點上跟現在逐位一樣，隨機的兩點快 10–18%。
- **只有這一件會跑在每一張圖上**：R090 其他的模擬改動（新地圖、尋路的新規則、人口）都只在地圖 5。先把這件單獨合進去，R090 的模擬改動就只碰地圖 5——跟 R096（找目標，逐位一樣）先於 R095 的做法一樣。

## 做什麼

1. `src/sim/path.ts`（90 行 → ≤ 105 行）：
   - 四個陣列與堆放在模組裡，只有地圖大小（n）變了才重開；
   - 每次呼叫怎麼「清空」：`fill()` 或每次呼叫加一的代號（陣列裡記「這格是第幾次呼叫寫的」）——兩個都寫出來，在同一次量測裡比，留快的那個，數字記在卡面；
   - 堆的鍵、展開的順序、平手的規則一字不差；守衛釘住的三行（`const i = z * n + x;`、`fl = goal > K - 1 - goal ? 1 : 0;`、`enc = …` 那一段）原樣保留。
2. 沒有閥：結果逐位一樣，新開的局、舊紀錄、存檔、連線都一樣，不需要也不應該有兩種。

## 不改什麼

- 模擬的結果：黃金雜湊 `eea1d59b`；任何一局的雜湊逐位不變（舊紀錄、存檔、連線合作與對戰）。
- `src/sim` 只改 `path.ts`；畫面、介面、`main.ts`、`battle.ts` 一行不動。
- 既有守衛不改（`tests/path-speed.mjs` 的 R064 參考答案、`tests/symmetry.mjs` 的兩處故意弄壞照樣要紅在原來那一句）。

## 驗收（動手前寫）

1. **卡面先**：第一個提交只有這張卡。
2. **只動該動的**：`git diff 74fa704 -- src` 只有 `src/sim/path.ts`；黃金雜湊 Node 與 Chrome 都是 `eea1d59b`；既有守衛不改、全綠。
3. **尋路逐位一樣**（新守衛 `tests/path-scratch.mjs`）：`74fa704` 的 `findPath`（型別剝掉、一字不差抄進守衛）與新的，在 ≥ 3,000 對問題上回傳一模一樣的路：
   - 地圖 0–4，加一張合成的 128×128（把 96 圖鋪滿 128 格）；
   - 對稱開、關；每一種兵；進房子、出房子；鐵絲網（徒步的擋、車不擋）；終點擋住的；起點等於終點、出界的；
   - 地圖大小輪流換（96 → 32 → 128 → 64 → 96），兩個世界交錯著問（暫存不能留著上一個世界的東西）。
4. **對打的雜湊一樣**：地圖 2 與 3、種子 1–10、電腦第三版困難對困難、擬真、`end`、`mg 2`、`pla`、12,000 步——每一局最後的雜湊與步數＝在 `74fa704` 凍結的（收據在卡面；守衛跑其中幾場短的）。
5. **不再配陣列**：暖過一次之後，同一張圖上再叫 `findPath` 不新開任何 typed array（守衛數建構子被叫幾次）；換了地圖大小才重開一次。
6. **不會變慢**：96 圖隨機兩點、全選 47 個單位的移動指令、128 圖同樣兩項，五次取中位數（先確認沒有別的無頭瀏覽器在跑）：都不比之前慢，數字記在卡面；`fill()` 與代號兩種的數字也記。
7. **純**：新的程式碼沒有亂數與時鐘；`tools/unit.mjs` 的模擬層純度（不准 `**`、只用整數的 Math）在本機先跑過（`UNIT_SHARD=1/200`）。
8. **故意弄壞**（隔離的複本，第一個紅的在指定的斷言上）：某個陣列沒清、堆沒清空、地圖大小變了沒重開、堆的平手鍵換掉、代號沒加一（若留代號）、起點的「從哪來」沒重設。
9. **總機**：`tests/hub-budget.mjs`、`tests/valves.mjs`、`tests/card-numbers.mjs` 綠。
10. **收尾**：卡面、LOG、路線圖（第 8 張註明 R097 是前置；卡號剩幾張）；R095 的合併資訊補進它的卡面、LOG、路線圖；`npm run check` 與 CI 綠。

## 風險

- **模組裡的狀態**：兩個世界交錯著問、地圖大小中途變了、上一次搜尋到一半拋錯——都要從乾淨的暫存開始（驗收 3 的交錯、驗收 8 的故意弄壞）。
- **代號滿了**：代號是 32 位元，滿了就重開陣列（一局遠遠用不到，守衛直接把代號推到快滿測一次）。
- **量時間的雜訊**：這台筆電同一件事兩次可以差兩倍；用中位數與同一次量測裡的比例。
- **省下的不多**：設計時量到配陣列只佔長路搜尋的一小部分（長路主要花在展開格子）；這張的價值是少丟垃圾（瀏覽器停頓）和讓 R090 的改動只碰地圖 5。尋路本身變便宜要靠 R090 只在地圖 5 用的新規則。
