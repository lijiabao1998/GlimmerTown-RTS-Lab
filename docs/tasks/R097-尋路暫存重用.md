## 為什麼做這張

路線圖第 8 張（R090 更大的戰場）跑了設計工作流（三份方案＋裁判，2026-11-18）。裁判選了 128×128 的新地圖（地圖 5），並把一件事拆出來先做：

- **每一次尋路都配一整張圖的暫存**：`findPath` 每叫一次就新開四個跟地圖一樣大的陣列（每格擋不擋、走到這格花多少、從哪格來、做完沒），再全部填一遍。96 圖一次約 92 KB、128 圖約 164 KB；全選 47 個單位下一個移動指令，128 圖一次就丟出 7.7 MB 的垃圾，瀏覽器要停下來收。設計時的原型（陣列重用）在 3,200 對起點終點上跟現在逐位一樣，隨機的兩點快 10–18%。
- **只有這一件會跑在每一張圖上**：R090 其他的模擬改動（新地圖、尋路的新規則、人口）都只在地圖 5。先把這件單獨合進去，R090 的模擬改動就只碰地圖 5——跟 R096（找目標，逐位一樣）先於 R095 的做法一樣。

## 施工紀錄

- **`src/sim/path.ts`（90 → 99 行）**：
  - 模組裡一組暫存：每格擋不擋（`memo`）、每格的地形速度（`spd`，新）、走到這格花多少（`g`）、從哪格來（`came`）、做完沒（`done`），加上堆。格數（n×n）變了才重開；每次呼叫先 `fill()` 成跟以前新開的陣列一模一樣（`g`、`came` 是 -1，其他 0），堆的長度歸零。
  - 堆：`Float64Array`、從 1,024 格起、不夠才加倍（舊的搬過去）；比較與搬動跟原本的 `number[]` 一步不差。
  - 取出：鍵在 (0, 2^53) 時，`v % M` 改成 `q = floor(v / M)、e = v − q×M`，再把可能差一的餘數修回 [0, M)（兩邊都是精確的：`q×M` 是準的整數、相減差不到兩倍）；其他的鍵（負的、0、NaN、2^53 以上）照舊 `%`。遊戲裡的鍵一定是正的，修正那一步實測從來沒有觸發，留著是保險。
  - 鄰格的啟發值算一次給兩個地方用（原本同一個值算兩次）；格子在不在圖內寫成 `!(nx >= 0 && nz >= 0 && nx < n && nz < n)`（跟 `inGrid` 一樣連 NaN 都擋），格索引直接寫在迴圈裡。
  - 地形速度：`stepCost` 改成收速度；每格的速度在一次搜尋裡只問 `speedPct` 一次（搜尋中世界不變，`speedPct` 只讀地形、房子、彈坑）。這一項省最多（每格平均被問好幾次）。
- **`fill()` 與代號**（同一次量測，兩版都有堆、取餘、啟發值三件，都還沒有「速度只問一次」，只差清空的方法）：96 圖隨機兩點 366.9／387.6 毫秒、全選 47 個 98.0／107.4、短路 3,721／3,895；128 圖隨機 609／633、全選 109／117、短路 41.6／34.8——96 圖 `fill()` 快、128 圖的短路代號快一點；留 `fill()`（常玩的 96 圖快、程式簡單，設計工作流裡 Engine 那份也量到代號比較慢）。
- **改過的地方與原因**：
  1. **`came` 原本打算不清**（往回走只會經過這次寫過的格，結果一樣）：`tests/symmetry.mjs` 的故意弄壞 `index_ties`（把次序編碼改壞）讓「展開的格都是這次推進去的」不成立，沒清的 `came` 讀到上一次的、往回走停不下來（陣列長度錯誤），沒有紅在它指定的那一句。改成每次照樣清成 -1，跟以前一模一樣。
  2. **範圍比卡面大**：卡面寫「重用陣列」；量到只快 2–5% 之後加了上面四件（都證明逐位一樣），寫進「做什麼」。
  3. **故意弄壞「格數變了沒重開」**：變大沒重開時陣列太小，讀到外面是 `undefined`，搜尋停不下來（逾時，不是紅在某一句）；改成「只在變大時重開」的突變（變小沒重開），紅在 alloc 那一句。變大沒重開由 identity 的大小輪換擋（會卡住、守衛逾時一樣是紅）。
  4. 守衛名字：卡面寫 `tests/path-scratch.mjs`（`path-speed.mjs` 是 R064 的，名字已經用了）。
  5. **審查**（兩個方向：結果逐位一樣、守衛擋不擋得住；每條都找人推翻；工作流 wf_37521251-832）確認 6 條、全修：
     - 座標不是整數時（遊戲裡的呼叫都是整數，存檔也檢查），手寫的邊界檢查放過 NaN，新版會無限推進堆、記憶體一直長（舊版搜完回傳空的）→ 邊界寫成跟 `inGrid` 一樣；
     - 彈坑深到 8 以上速度變負數（遊戲裡彈坑最多 3；手改的存檔讀得進來），堆的鍵變負，除法修正跟 `%` 的負餘數不一樣、路不同 → 只在鍵是 (0, 2^53) 時走除法；
     - 守衛缺的四件：搜到一半拋錯之後沒有測（加 throw 群：讓 `w.wires` 第 N 次被讀時拋，下一題要跟參考一樣；故意弄壞「清空搬到搜完之後」紅在這裡）；identity 每一題都換世界、只改到第 10 個世界，同一個世界上改了彈坑再問的情形沒測（改成每個世界連問 4 題、每 7 題改一下當下的世界；故意弄壞「只在換世界時才清速度／擋路」紅在 identity）；重用只發生在 32、64 圖、卡面寫的大小順序也不對（改了之後重用 32：1,216、64：366、96：454、128：240 次，守衛有下限）；變大沒重開只會逾時（alloc 加「變大也重開」那一句，負面守衛斷言這個突變跑不完）。
