## 為什麼做這張

業主 2026-11-16：「更大规模 小兵班」。R089 讓一班看起來是十個人，但玩起來沒有變：電腦最多留兩班步兵（實際量到一局平均同時 1.08 班）、人口上限算單位（32 格的圖 16、64／96 圖 40）、多選移動的隊形第 10 個單位起重疊、沒有「排」。

設計跑了工作流（三個人讀模擬、電腦、介面，三份方案＋裁判；`scratchpad/r095/`）：
- 「步兵排」：一次出三班、整排選取、人口提高、電腦會出排（裁判 18／20）；
- 「排部當指揮單位」：排長與傳令兵、靠近排部的班恢復快（9／20：只有士氣第二版才有作用，經典規則的局看不到；新種類會碰到很多守衛）；
- 「人數算數」：剩幾個人打多少、一發最多打倒幾個人、人口照人數算（9／20：一次改四條規則，平衡關卡容易卡死）。

裁判選「步兵排」，嫁接「人數算數」的三點（介面看世界的旗標、`cdp.mjs` 的預設、每班自己的集結點），並量到兩件要在人口提高之前做的事——那兩件拆成 R096（找目標加速、畫面超過 800 人時少畫）。裁判也量到：**起手就送一個排會讓困難打普通從 84% 掉到 59%、擬真規則更差**，所以不送；只有困難的電腦換成會出排。

## 做什麼

**一定要做**

1. **新開的局的旗標** `eco.pla=1`：跟著第 0 步的 `eco` 指令送、只在第 0 步存；只在有的時候算進雜湊（`eco` 的 `0x5041` 接在 `mg` 後面，單位的 `0x504c`（`u.pl`）接在 `rout` 後面；兩個都還沒人用）。`?noR095=1` 不送。**排的介面看世界的旗標**（`w.eco.pla`），不看自己這一台的閥：連線時兩台閥不一樣也一樣。

3. **讀佇列的地方都經過 `queueKinds`、`ticksOf`、`costOf`**：`eco.ts`、`ai.ts`、`ai3.ts`、`main.ts` 的生產列；倒數與「為什麼不能按」包在新的介面檔裡（`productionCountdown.ts`、`productionBlockReason.ts` 不動，R125／R126 的故意弄壞錨在它們上面）；「人口滿了」的理由照舊沒有（`tests/production-block-reason.mjs` 釘住）。
4. **人口上限（有旗標時）**：32 格的圖 16 → 24、64 圖 40 → 56、96 圖 40 → 64。

6. **全排**：一顆觸控按鈕與桌機的 `P`（今天沒有用）叫同一個函式：選取「跟選著的班同一排的、活著的班」。
7. **電腦（第三版，只有困難、有旗標時）**：困難本來的兩個支援單兵換成「排」：核心 ≥ 4、班數 × 2 < 核心、班數 < 3（64／96 圖 < 6）時買一個排。簡單、普通不變。

**最好做**
- HUD 上「第 N 排」的字。
- 困難（第三版、有旗標）不把班送進已經有自己的班的房子。
