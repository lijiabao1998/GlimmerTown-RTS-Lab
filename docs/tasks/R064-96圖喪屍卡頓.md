## 為什麼做這張

R130 加了 96×96 河鎮。Claude 2026-10-26 量喪屍模式的壓力局（指揮部每步補滿血、48 群一直圍著；Node 桌機）：

| 地圖 | 每步 p50 | p99 | 最慢 |
|---|---|---|---|
| 96×96 | 6.9ms | 18.9ms | 85ms |
| 64×64 | 2.1ms | 4.0ms | 37ms |
| 萊伊 | 1.3ms | 1.9ms | 12ms |

96 圖的 p99 回到 R059 修之前 64 圖的水準，手機上會頓。CPU 取樣：`zombieAim` 43%（每隻喪屍每步兩次把全鎮每棟房子都算一次距離，還先把房子清單複製一份），A* 連同它的小函式約 40%（每格「擋不擋」在一次搜尋裡被問最多十次，鐵絲網每次都從頭找）。

## 做什麼

1. `src/sim/zombies.ts` `zombieAim`：
   - 沒被擋住時只有指揮部可能被選（原本的規則），就只看指揮部，不掃全鎮；
   - 被擋住時先用格子篩：離房子超過 m 格一定碰不到（m 照近身距離算、寧多不少），才算距離；
   - 不再複製房子清單。
2. `src/sim/path.ts` `findPath`：每格擋不擋在一次搜尋裡只算一次（記在一張跟地圖一樣大的表）。所有單位都用這支，一般對戰的大地圖也一起變快。
3. 守衛 `tests/path-speed.mjs`：
   - 把 main `263ab52` 的 `path.ts` 原文（型別剝掉）貼進守衛當參考答案，四張地圖＋鐵絲網、坦克／步兵／喪屍、進出房子共 600 個尋路問題，答案逐格相同；
   - 喪屍挑房子：96 圖每棟房子四周各種位置、擋住／沒擋住，跟改之前的掃法逐一比；
   - 喪屍模式 64、96 圖 3000 步雜湊凍結在改之前算的值。
4. `tests/path-speed-negative.mjs`：故意弄壞兩處（快取記錯格、格子篩太緊），各紅在自己那一句。

## 不改什麼

## 施工紀錄

- `zombieAim`：把「擋住了沒」提到迴圈外（它本來就跟哪棟房子無關）；沒擋住只看指揮部；擋住時先用格子篩（m＝⌊(近身距離＋半格)／一格⌋＋1，近身 1 格時 m＝2，比剛好需要的 1 格寬一格），再照原本算距離挑最近的；房子、鐵絲網照原本順序各掃一次，平手時誰先誰勝不變。
- `findPath`：一張 `Uint8Array`（0 沒算、1 可走、2 擋）記每格擋不擋；只在格內問，用到的式子跟原本一字不差。
- 守衛把舊 `path.ts` 原文剝型別貼進去當參考答案，不靠 git 歷史（CI 是淺複本）。
- 第一版只用「3000 步雜湊凍結」驗喪屍挑房子，故意把格子篩弄到 0 格時雜湊沒變（3000 步內沒有喪屍貼到牆）——守衛太鈍，改成直接拿改之前的掃法逐一比 1,704 個位置。
