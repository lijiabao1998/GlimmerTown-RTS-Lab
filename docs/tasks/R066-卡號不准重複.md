## 為什麼做這張

2026-10-28 兩個開著的 PR 都用了 R904：#101（教學打磨，lijiabao3）、#102（手機直向打磨，lijiabao4）。R900–R999 是 Grok 線的段（R900），Grok 與它派出的代理一起用，沒有任何守衛擋重號；GPT 車道的 `gpt-lane` 只管 `gpt/*` 分支。兩張都綠，誰先合誰拿號，後合的那張卡面、LOG、PR 標題全都要改。

## 做什麼

1. 守衛 `tests/card-numbers.mjs`：`docs/tasks/` 裡一個 R 號只能有一個檔；`LOG.md` 表格裡一個 R 號只能有一列。紅的時候寫清楚是哪幾個檔／哪一號、怎麼改（後來的那張改成沒人用過的號）。同一支守衛裡用假資料各做一次重號，確認紅得出來。
2. 規則：`AGENTS.md` 第 0 節卡號那條加一句「一個號只能有一張卡、LOG 一列；R900–R999 由 Grok 線與它派出的代理共用；開卡前看 `origin/main` 的 `docs/tasks/`、`LOG.md` 與所有開著的 PR，拿沒人用過的號」，第 2 節第 10 條的 Claude 結構守衛加上這支。
3. GPT 車道：`tools/gpt-lane.mjs` 把 `tests/card-numbers.mjs` 列進 Claude 的結構守衛（GPT 不改）；`tests/gpt-lane-claude-tests.mjs` 多驗這一支。

## 對其他車道的影響（照實寫）

- 任何車道開出重號的卡，PR 的 unit 會紅在 `card-numbers`。兩張同號的 PR 都還沒合時，各自的 CI 抓不到（比的是合併後的樣子）；先合的那張進 main 之後，後一張一合 main 或重跑 CI 就會紅。
- GPT 不能改 `tests/card-numbers.mjs`。

## 不改什麼

- 產品程式、模擬、黃金雜湊都不動；不改已經在 main 上的卡號（現在沒有重號）。

## 驗收（動手前寫）

1. `tests/card-numbers.mjs` 在 main 上綠；假資料兩張 R904、LOG 兩列 R904 各紅一次，訊息寫出那個號與檔名。
2. `tests/gpt-lane-claude-tests.mjs`：GPT 改 `tests/card-numbers.mjs` 被擋；改自己的守衛照樣放行；負控（拿掉規則）會放行。
3. `AGENTS.md` 第 0 節與第 2 節第 10 條改好。
4. 全套 CI 綠。

## 施工紀錄

- `tests/card-numbers.mjs`：檔名開頭 `R` 加剛好三位數才算卡號（`R134-接續R131…` 只算 R134）；LOG 只看表格列開頭 `| R### |`。紅的訊息寫出撞號的號、檔名或列數，以及怎麼改。
- 同一支守衛先跑負控：兩張 R904 卡、兩列 R904 都要被抓到；不同號、標題裡出現別的號、四位數檔名都不算。
- `tools/gpt-lane.mjs`：`CLAUDE_TESTS` 多一個 `card-numbers`，擋下的理由寫明撞號怎麼辦。
- `tests/gpt-lane-claude-tests.mjs`：夾具多放一個 `tests/card-numbers.mjs`，GPT 改它被擋；拿掉規則的負控對它也會放行。
- `AGENTS.md`：第 0 節卡號那條、第 2 節第 10 條。

### 沒做成的事

- 兩張同號的 PR 都還沒合時抓不到：各自的 CI 比的是「自己合進 main 之後」的樣子。要在開 PR 時就擋，得在 CI 裡列出所有開著的 PR 互比（要改 `.github/`，而且要讀 PR 清單的權限），這張沒做。
