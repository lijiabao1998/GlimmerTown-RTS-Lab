## 為什麼做這張

業主 2026-10-27 問「程式碼黏在一起、越來越長」怎麼看。Claude 量了 main `263ab52`：

- `src/main.ts` 761 行，最近 30 次合併有 21 次動到它；52 個 `?noR<號>` 逃生閥散在檔案各處讀（`q.get('noR…') !== '1'` 60 處）。
- 畫面類別 `BattleView` 的建構子吃 15 個照順序排的真／假參數；`main.ts` 裡建畫面寫了兩份（開局 `reset()` 與守衛用的 `runScript()`），建完再各自補設兩個欄位。新卡要加一個畫面開關，就得在建構子、兩份呼叫、`recreate()` 各補一次，排錯順序也不會報錯。
- 兩份呼叫已經不同步：`runScript()` 少了 `!w.sandbox &&`。腳本世界不會是沙盒，所以目前沒有實際影響，但這正是位置參數會出的錯。

業主同意整理，這張是第 1 步。

## 做什麼

1. **一張閥表** `src/valves.ts`：每個 `?noR<號>` 一行 getter（`get r124() { return on('124'); }`），旁邊是原本那句說明。每次讀都看網址當下的值（跟原本逐處讀 `q` 一樣：守衛在頁面上改網址參數照樣生效）。
2. `main.ts` 讀閥一律 `V.r<號>`；原本散在頂部的 `const r0xx = q.get(…)` 與說明搬到閥表，`main.ts` 少掉約 50 行。
3. **畫面設定物件**：`new BattleView(w, { fx, fog, observerDetails, r004, … , rubbleMarks, multiRange })`，沒寫的欄位預設開；`recreate()` 用同一份設定。
4. **建畫面只寫一處**：`main.ts` 一個 `makeView()`，開局與 `runScript()` 都呼叫它。
5. 跟著改守衛：直接 `new BattleView(...)` 的 Node 守衛改傳設定物件（逐一對照原本每個位置代表的開關）；錨在舊寫法上的守衛與故意弄壞改錨到新寫法，**語意不變**（同一個斷言、同一個紅燈）。

## 不改什麼

- 模擬、黃金雜湊、任何畫面與介面行為都不變；每個舊閥照舊關得掉，關掉的效果跟原本一樣。
- 不刪閥、不改閥名、不改網址參數。
- 不動 `.github/`、`tools/`（R061 再加長度守衛）。
