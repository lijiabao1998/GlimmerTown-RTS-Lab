## 為什麼做這張

R060 之前，`src/main.ts` 最近 30 次合併有 21 次被動到，從 10/18 的 349 行長到 761 行；`src/render/battle.ts` 1,410 行。兩個檔是「總機」：每張卡都往裡加，越加越長，也最容易兩條車道同時改到同一段。業主同意加一條守衛：這兩個檔的行數只准變少。

## 做什麼

1. **上限檔** `tools/hub-budget.json`（`tools/` 只有 Claude 能改）：每個總機檔一個行數上限。上限只往下調，不往上調；每次 Claude 整理把檔變短，就在同一個 PR 把上限調低。
2. **守衛** `tests/hub-budget.mjs`：兩個檔的行數都不超過上限；印出各還剩幾行。
3. **留一點接線空間**：上限＝現在的行數＋20 行。新功能寫在自己的檔，總機只加接線（一兩行）；空間用完，要先把總機裡別的東西搬出去才能再加。
4. **規則寫進 `AGENTS.md` 第 2 節**：總機只放接線；新閥加在 `src/valves.ts`（R060）；行數上限在 `tools/hub-budget.json`。
5. **GPT 車道**：`tools/gpt-lane.mjs` 把 `tests/hub-budget.mjs`、`tests/valves.mjs` 列為 Claude 的守衛，GPT 不改（上限檔本來就在 `tools/`，GPT 改不到）。

## 對 GPT 車道的影響（照實寫）

- GPT 加功能時，`main.ts`／`battle.ts` 只能加接線；總機裡剩的空間不夠時，GPT 的 PR 會紅在 `hub-budget`，要先把總機裡的東西搬出去（或寫成自己的檔再接一行）。
- 新的 `?noR<號>` 閥加在 `src/valves.ts` 一行，不要在 `main.ts` 讀網址（R060 的守衛 `tests/valves.mjs` 會擋）。
- GPT 不能改 `tests/hub-budget.mjs`、`tests/valves.mjs`；改了 `gpt-lane` 會紅。

## 不改什麼

- 產品程式、模擬、黃金雜湊都不動。

## 驗收（動手前寫）

1. `tests/hub-budget.mjs` 在 main 上綠；把任一個檔多加超過空間的行數（隔離副本）紅在那個檔名。
2. 上限檔只有 `tools/` 一份；守衛讀它，不在守衛裡寫死數字。
3. `tools/gpt-lane.mjs` 擋 GPT 改 `tests/hub-budget.mjs`、`tests/valves.mjs`：用既有的 `tests/gpt-lane-card-number.mjs` 同樣的隔離 git 夾具驗一次紅、一次綠（改別的守衛照樣放行）。
4. `AGENTS.md` 第 2 節多一條總機規則。
5. 全套 CI 綠。
