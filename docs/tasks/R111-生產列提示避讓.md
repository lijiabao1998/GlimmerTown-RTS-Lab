# R111：生產列隨提示高度同步避讓
<!-- card: sim=no; golden=無; valve=無; owner_ok= -->

## 為什麼做

待辦21。R110 真實手機樣張證明：生產列邊框會穿過多行提示的第一行，且在砲擊提示出現前就存在。`production.ts` 將生產內容與位置共用 supply／queue／prog 快取；暫停時提示變高，內容沒變就提前返回，連120次更新也不重新避讓。這是既有介面修補，沒有新視覺效果，故 valve=無；保留 noR109 等既有閥。

## 做什麼

只分離生產列的內容快取與布局失效條件，使提示內容、提示元素、視窗大小或重新顯示改變時，同步重新計算原本的底部距離。保留內容沒變不重寫按鈕／補給／佇列的快取；穩定畫面不反覆量幾何。補純DOM守衛與真實Chrome回歸、語意負控制及手機特寫。

## 不改什麼

不改模擬、指令、傷害、AI、步兵專屬機制、黃金雜湊、CSS樣式、顏色、鏡頭、後製、手機預算、套件、工具／CI與規則檔。不重做布陣列或把其他布局問題夾進本卡。不改R109手勢、R110清除提示語義與既有驗收。

## 驗收（動手前寫）

1. 暫停且 supply／queue／prog 不變時，提示由短變多行、再變短後，生產列在下一次既有 update 立即避讓，仍用原公式 `max(8, innerHeight - hint.top + 6)`；手機真實DOM上生產列底邊不越過提示頂部減6px，不再壓住文字。
2. 寬度或高度改變、提示元素替換、初始隱藏再顯示、隱藏期間改提示或視窗，都重新取得位置；找不到提示元素時不誤記布局已完成，之後出現仍可正常定位。沒有提示時不例外，不引入非同步觀察器造成選單避讓讀到舊位置。
3. 內容快取與布局分開：穩定120次 update 不增加 hint 幾何讀取或 bottom 寫入；只變補給／佇列／進度而提示與視窗不變，不需要重新量測提示。布局變但生產內容不變，不重寫按鈕、補給、佇列或進度；按鈕仍只發出一次原kind生產呼叫。
4. 真實Chrome在412×860暫停場景驗證選取長提示、砲擊成功／失敗提示、清除後提示以及手機／桌機尺寸切換；經濟值不前進時仍不重疊。同步 `HUD.update → production.update → menu.open` 保持成立；選單位置依已更新的生產列避讓。noR109=1下仍正常；既有R110提示清除與前後幾何相等守衛不削弱，命令數／內容、tick／hash保持預期。
5. 新增守衛直接執行正式production程式；各新守衛組至少一個獨立正式程式語意變異，第一個紅燈落在該組布局／快取斷言，語法或啟動失敗不算。真實瀏覽器新增覆蓋亦有隔離暫存bundle負控制；不把測試掛勾放進正式build。既有守衛不改門檻，完整unit仍在既有120秒單支限制內。
6. typecheck／unit／build／smoke依環境執行，Chrome使用明確CHROME_PATH；本機不能啟動要照實記錄，不稱全綠。模擬、golden逐位不變，Node／Chrome腳本hash維持600 tick c789deeb、1200 tick f3364bb6，JSON／clone守衛保留。手機開局≤20 calls／80k triangles，戰鬥特寫≤22／80k，不增加WebGL幾何或繪製。
7. 看最新提交CI的桌機／手機開局與30秒四張標準圖，以及修補前後手機提示特寫；不宣稱Android實機已測。獨立審查、卡面實際結果／沒做成的事、方向待辦／完成表及LOG收尾齊全；最新main版lane、最新head CI與合後main CI／Pages均需通過。
