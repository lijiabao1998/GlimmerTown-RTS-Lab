## 為什麼做這張

北極星是「打開會玩一整天的二戰遊戲」。現在一局可以打二三十分鐘，但只要關掉分頁、手機切去回個訊息被系統收掉、不小心重新整理，那一局就沒了。R047 存的是打完的局（重播），打到一半的沒有地方留。

模擬從第一張卡起就要求「狀態全部在 `World` 裡，中途深拷貝接著跑等於直接跑」，每張改模擬的卡都有守衛驗這件事。所以存檔不用發明新東西：把整個世界存下來、讀回來，就能接著打。

同時把 R051 在 `LOG.md` 那一列缺的 CI 編號補上。

## 做什麼

### 1. 模擬：世界的編碼與解碼（只加不改）

- 新檔 `src/sim/worldCodec.ts`：`encodeWorld(w)` 把世界轉成可以 `JSON.stringify` 的東西，`decodeWorld(x)` 轉回來。
- 世界裡大部分是普通的數字與陣列，直接留著；地形、建築佔格、彈坑、植被那幾張整張圖大小的表，用「值、連續幾格」的寫法壓起來（地形多半是大片相同的值）。只給畫面看的事件清單不存。
- 轉回來的世界：`hashWorld` 跟原本相同；接著跑跟原本接著跑逐位相同。形狀不對的東西（不是物件、邊長離譜、表的長度對不上）回傳 `null`，不丟例外。
- 不改 `step()`、`hashWorld`、任何既有欄位。

### 2. 存檔（第 1 版，鍵名 `gtrts.v1.save`，只有一格）

```ts
{ v: 1, at, seed, tick, hash, world, log, cam }
```

- `world`：上面編碼過的世界。`log`：到目前為止的指令紀錄（讀回來之後這一局打完照樣能存成重播）。`hash`、`tick`、`seed`：存檔那一刻的，讀的時候用來驗。`cam`：鏡頭位置與縮放（只影響畫面）。`at`：時間。
- **什麼時候存**：開戰之後，每 5 秒看一次，世界有往前走就存；分頁被切到背景、頁面要離開時再存一次；從暫停選單按「回主選單」時先存一次。
- **不存的**：布陣階段（還沒開戰，沒有東西可接）、沙盒、正在看的重播、已經分出勝負的局。**分出勝負就把存檔清掉**（那一局已經在重播裡了）。
- 存不了（隱私模式、空間滿、超過 150 萬字）就不存，不報錯。

### 3. 讀檔與驗證

讀回來要全部成立才算有存檔，少一條就當作沒有：

- 是第 1 版；`seed`、`tick`、`hash`、指令紀錄（用 R047 的 `checkLog`）格式都對；
- 世界解得開；它的種子、步數等於紀錄寫的；`hashWorld` 等於紀錄寫的；
- 還沒分出勝負、不是沙盒；
- 拿一份複本先走一步，不丟例外。

### 4. 選單

- 有存檔時，開頁的開始選單最上面多一顆「繼續上一局」（主鍵），下面一行小字：哪張圖、打到幾分幾秒、種子。「開始」排第二顆。沒有存檔時選單跟現在一模一樣。
- 按「繼續上一局」：世界、指令紀錄、鏡頭換成存檔裡的，**先停在暫停**（讓人看清楚狀況再按 ▶）。之後「重新開始」會用這一局的地圖、模式、難度、兵力、補給、種子重開。
- 布陣中從「選單」鍵叫出的選單、開戰後的暫停選單不出現這顆鍵。

### 5. 接線與守衛

- 新檔 `src/sim/worldCodec.ts`、`src/ui/saveGame.ts`。`src/valves.ts` 加 `r074`；`README.md` 補說明。
- `src/main.ts`：一行 import、一行接線。為了不超過 673 行，先騰出兩行：兩個從 `./render/battle.ts` 來的 import 併成一行、`issue()` 前面連續兩個空行拿掉一個。做完仍是 672 行。
- `src/ui/startMenu.ts`：「繼續上一局」鍵；「回主選單」先存。`src/ui/skirmish.ts`：多一個「照這個世界把設定對齊」的動作（讓「重新開始」與 R073 的記憶跟上接回來的這一局）。
- `tools/cdp.mjs`：`open()` 預設開頁前也清掉 `gtrts.v1.save`（`{ keep: true }` 保留）。`AGENTS.md` 第 3 節第 6 條同步。
- 新守衛 `tests/savegame.mjs`（不開瀏覽器）、`tests/savegame-browser.mjs`（真 Chrome）。
- `LOG.md`：R051 那一列補 CI 編號。

## 不改什麼

- 黃金雜湊 `eea1d59b`、`step()`、`hashWorld`、指令格式、所有舊紀錄。
- R047 的重播、R073 的設定記憶的格式與行為。
- 只有一格存檔，不做多格、不做命名、不做匯出匯入（重播已經能匯出）。
- 手機預算；整張畫面的觀感。

## 驗收（動手前寫）

**編碼與解碼**（Node）

1. 來回：取幾個打到一半的世界（萊伊；鄉間 64 加 R046 的規則與 R051 的穿甲；河鎮 96；喪屍防守；有布陣的房子、戰壕、鐵絲網、煙幕、反砲兵情報、補給與生產、雙方電腦），`encodeWorld` → `JSON.stringify` → `JSON.parse` → `decodeWorld`：`hashWorld` 與原本相同。
2. 接著跑：解回來的世界與原本的世界各自再跑 300 步（帶同一份指令紀錄），雜湊相同，也等於從頭一路跑到那一步。
3. 世界裡每一個整張圖大小的表（型別陣列）都有被編碼：編碼結果裡沒有型別陣列，轉成文字再轉回來不會掉東西。
4. 拒收：`null`、數字、陣列、缺邊長、邊長是 0 或小數或大到離譜、表的格數加起來不等於邊長平方、表裡有負的連續格數——都回傳 `null`，不丟例外。

**存檔紀錄**（Node）

5. 一筆合格的存檔通過檢查，拿回來的世界雜湊等於紀錄。下面每一種都被拒絕並有原因：不是 JSON、`v` 是 2、`hash` 跟世界對不上（改掉世界裡一個單位的血量）、`tick` 或 `seed` 跟世界對不上、指令紀錄有壞指令、已經分出勝負的世界、沙盒世界、超過字數上限。
6. 儲存（假的 storage）：存了讀得回來；壞掉的字串讀成沒有；一碰就丟例外的 storage、沒有 storage，讀寫清除都不丟例外；清除之後讀成沒有。鍵名以 `gtrts.v1.` 開頭。
7. 隔離副本故意弄壞至少三處，第一個紅燈各落在自己的斷言：編碼漏掉彈坑、解碼不檢查格數、存檔檢查不比雜湊。

**遊戲裡**（真 Chrome）

8. 開戰、下幾道指令、走一段之後觸發存檔（守衛送頁面離開的事件）：本機有一筆，`tick`、`hash` 等於當下的世界。布陣階段觸發不會存。
9. 重新開頁（保留本機資料）：開始選單第一顆是「繼續上一局」，小字有地圖與時間；按下去——遊戲在開戰階段、暫停著、步數與雜湊等於存檔那一刻；指令紀錄是存檔裡那一份。
10. 接回來之後再走 200 步，雜湊等於原本那一局沒有中斷、走到同一步的雜湊（決定性跨過存檔）。
11. 接回來的那一局打到分出勝負：R047 的重播照樣存一筆，而且拿那一筆從頭重播雜湊對得上；存檔被清掉，回開始選單沒有「繼續上一局」。
12. 「回主選單」會先存：開戰後叫出暫停選單按「回主選單」，開始選單就有「繼續上一局」，按了回到剛才那一步。
13. 大地圖、喪屍防守、開著 R051 規則的局各接回來一次：地圖邊長、模式、規則都對；之後按「重新開始」是同一種局（地圖、模式、兵力設定相同）。
14. 壞掉的存檔（文字被截斷、`hash` 被改）：選單沒有「繼續上一局」、頁面零錯誤。沙盒不產生存檔。正在看重播時不產生存檔。
15. 版面：有「繼續上一局」的開始選單在 412×915、360×780、860×412、1280×800，每顆鍵至少 44×44、整顆在畫面裡、點得到，不用捲動。
16. 逃生閥 `?noR074=1`：不存、不讀、沒有這顆鍵；黃金雜湊不變。
17. 故意弄壞三處，各紅在自己的斷言：不存、接回來的不是存檔的那個世界、壞掉的存檔照樣給按。
18. `main.ts` 行數不超過 673；`tools/cdp.mjs` 預設清掉存檔，既有守衛不受影響；全套 CI 綠。附手機樣張（有「繼續上一局」的選單、接回來暫停著的畫面）。
