## 為什麼做

桌機（滑鼠＋實體鍵盤）現在只有滑鼠拖曳、滾輪、空白鍵、Esc、右鍵；`R143` 的浮動「開火／停火」鍵是為手機拇指放的左側直欄，桌機擺在工具列下方、地圖左緣，既擋地圖又不像桌機 RTS 的操作方式。業主要求桌機去掉那顆鍵、WASD 平移、補上標準 RTS 按鍵。

## 做什麼

1. 新檔 `src/ui/keys.ts`：純函式（按鍵→動作、按住→每幀位移）＋ DOM 接線，跟 `src/ui/camera.ts` 一樣不碰世界。
2. `src/main.ts`：只加接線（`initDesktopKeys` 一處、主迴圈一行 `step(dt)`），新增的實際行為都在 `keys.ts`。
3. 桌機鍵表（`?noR070=1` 全部關掉）：

| 鍵 | 動作 |
|---|---|
| W A S D／↑ ← ↓ → | 平移鏡頭，按住連續移動（1100 CSS px／秒，斜走不加速），放開即停 |
| Q／E、+／− | 縮小／放大一格（1.12 倍，與滾輪同倍率，沿用 0.55–3 的既有範圍） |
| H | 鏡頭回我方指揮部（沒有指揮部時回我方單位重心） |

| Ctrl+A | 全選我方 |
| 1–9／Ctrl+1–9 | 選群組／設定群組 |

| F1／? | 說明面板 |

   Space（暫停）與 Esc（取消選取）維持原本在 `main.ts` 的處理，不動。
4. `src/ui/fireDiscipline.ts`：新增 `toggleFireDiscipline()`（按鈕與 G 鍵共用同一段），並在桌機不建立那顆浮動鍵（`opts.show`）。
5. `src/valves.ts`：新增 `r070`。
6. `src/ui/help.ts`＋`index.html`：說明面板加「桌機按鍵」一段，`body.r070` 才顯示。

### 沒做成的事

1. **沒有真手機、沒有真桌機量測**：只有無頭 Chrome 的媒體查詢與 DOM 斷言；「用起來順不順」要業主自己開一局。
2. **第 9 條的整張樣張對照沒做**：只比了浮動鍵與工具列，沒有把 `?noR070=1` 與 `db9eedc` 的 1280×800 畫面並排拍圖（要拍得先切回舊版建置，這次沒做）。
3. **`tests/bombard-status-browser.mjs` 的「桌面」其實是 coarse**：它全程開觸控模擬，改不到真正的桌機路徑；這張只讓 `fire-discipline-browser` 覆蓋桌機段。
4. **沒有量按鍵平移的實際幀率影響**：`step()` 只做幾個 Set 查詢與一次 `view.pan`，沒有單獨計時；也沒有在手機上驗（手機根本沒掛這條）。
5. **`Esc` 沒有擴大成「先關說明／戰報」**：原本的行為照舊，這張不動它（怕動到既有守衛的語意）。
6. **底部提示沒有換成桌機字樣**：`paused-hint.mjs` 釘死「點我方單位（藍圈）選取；拖曳平移，雙指或滾輪縮放」，所以桌機玩家只能從「？」說明面板看到按鍵。要改那句得先改一支既有守衛，另外開卡。
7. **一共動到三支既有守衛**：`fire-discipline-browser`（業主 2026-11-02 同意）、`input-timing`（只補 `pickUnitAt` 符號）、`bombard-status-browser` 沒動。業主只點名同意前兩支的桌面段，`input-timing` 的符號補充是搬檔的必要動作，已在 PR 內文單獨列出，請業主過目。
