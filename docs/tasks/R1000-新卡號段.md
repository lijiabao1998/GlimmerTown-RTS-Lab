## 為什麼做這張

R099 請業主再劃一段卡號。業主 2026-11-19 回答：「你來決定吧，反正卡號別衝突就行」。

Claude 選 **R1000–R1099**（R099 的選項 A）。理由是它跟兩條車道都撞不到：

- GPT 車道用 R100–R899。`tools/gpt-lane.mjs:83` 算「卡號要比 main 上用過的大」時，只看 R100–R899 之間的號。所以 Claude 的四位數卡不會把 GPT 的號往上推，GPT 也拿不到 R900 以上的號（第 85 行）。
- Grok 用 R900–R999。

「別衝突」不只是號不撞，守衛也要看得懂新的號。現在有三處看不懂：

| 檔案 | 現在 | 會怎樣 |
|---|---|---|
| `tests/card-numbers.mjs:9`、`:13` | 只認 `R` 後面剛好三位數 | `R1000-*.md` 被當成沒有卡號：兩張 R1000 撞號抓不到 |
| `tests/valves.mjs:17` | 閥表只認 `get r` 後面三位數 | 之後的卡加 `?noR1001=1` 這種閥，閥表守衛數不到它 |
| `tools/gpt-lane.mjs:63` | GPT 能改的卡是 `R(?!0\d\d-)\d{3,}-`，只把 R001–R099 擋在外面 | GPT 的 PR 可以改 Claude 的 `R1000-*.md`（R001–R099 的卡它改不到） |

`tests/readme.mjs` 用 `\d+`，本來就認得四位數，不用改。CI 工作流裡沒有讀卡號的地方。

## 做什麼

1. `tests/card-numbers.mjs`：卡檔名、LOG 第一欄都認 `R` 加三位數，或 `R1` 開頭的四位數（`R(\d{3}|1\d{3})(?!\d)`）。故意弄壞的夾具加：
   - 兩張 R1000 抓得到、LOG 兩列 R1000 抓得到；
   - R1000 跟 R100 是不同的號；
   - `R10000-*.md`、`R0661-*.md` 都不算卡。
2. `tests/valves.mjs`：閥表的 `get r…()` 認三或四位數。
3. `tools/gpt-lane.mjs`：
   - 第 63 行白名單把 `R10\d\d-` 也擋在外面（GPT 改不到 Claude 的 R1000–R1099 卡）；
   - 第 84 行的說明寫上兩段。
   - **影響 GPT 車道**：GPT 本來就不能用 R1000 以上的號（第 85 行），這張只是把「改 Claude 的卡」那一條補齊；GPT 自己的卡（R100–R899）照舊。
4. `tests/gpt-lane-claude-tests.mjs`：
   - 加兩幕：GPT 改既有的 `R1000-*.md`、`R030-*.md` 都被擋，理由是「白名單以外」。
   - 故意弄壞：白名單換回舊的寫法時，R1000 那一幕放行。
   - `tests/gpt-lane-card-number.mjs` 加一幕：GPT 開 R1000 的卡被擋。
5. 文件：
   - `AGENTS.md` 第 11 行、`CLAUDE.md` 第 9 行、`docs/DECISIONS.md` 第 47 行寫上新號段；`docs/DECISIONS.md`「已定」表加業主原話。
   - `docs/ROADMAP.md`：卡號計數、新段預留：
     - R1001 天候畫面（原 R030，R030 借給了 R092 運輸修補）；
     - R1002 步兵支援兵器（二）：工兵、火焰噴射器（R091 第二段）。
   - R099 卡面的狀態、`LOG.md` 的 R099 那一列寫上業主的回答。
   - R030（#152 → `c3356ed`）的合併資訊補進 R030 卡面、`LOG.md`。
