## 為什麼做這張

R055 量到：電腦對電腦（雙方一樣的設定）時，左上那一方佔便宜——丘陵經典 50 局右下只贏 1 局。病根不是地圖，是引擎原本就有的左右不對稱（R055 卡面「左上偏心的病根」）：最大的是多選移動的**編隊偏移表**偏向 +x、+z——右下那一方（往左上打）的隊員排到目標後面、左上那一方的排到前面；其餘是指揮部位置、出生格、集結點的取整與平手，尋路平手時偏向小編號。

接下來的 R085 是兩個人對打：一個人指揮右下、一個人指揮左上。引擎偏一邊，對打就不公平。這張卡把這些地方改成「左上那一方在鏡像座標裡做同樣的事」，放在新旗標後面（不然每一個舊重播都對不上）。

## 做什麼

1. **旗標**：`map` 指令多一個 `sym: 1`（只在第 0 步、只看第一個 `map` 指令），世界多一欄 `sym`、只在有時折進雜湊。新開的局送 `sym: 1`；逃生閥 `?noR084=1` 不送。
2. **編隊**：左上那一方用鏡像的偏移表（雙方都排到目標靠自己家那一邊）。
3. **指揮部的位置**：一樣遠的候選，左上那一方照鏡像的次序挑。
4. **出生格**：離「真的中央」（兩倍座標；原本用 `n >> 1`，不是中央）；平手照鏡像。
5. **集結點**：指揮部「朝中央那一欄」照鏡像（原本雙方都用 `hq.x＋1`）。
6. **尋路平手**：堆的次序從「格索引」換成「這一格與它的點鏡像那一格裡小的那個」——一條路與它的鏡像在平手時做一樣的選擇（不用知道是哪一方）。

## 不改什麼

- 沒帶 `sym` 的紀錄：黃金雜湊 `eea1d59b`、R081 的四局 `mg: 1`、四局蘇聯與國際兵種、R055 丘陵開局的雜湊都不變。
- 畫線（`lineCells`）、`cellOf` 剛好在格線上的取整、單位照編號處理的先後、電腦想事情時的平手次序：這張卡不動（寫進「沒做成的事」，附量到的剩下多少）。
- `main.ts` 行數不變（`map` 指令那一行多一個欄位）。

## 驗收（動手前寫；上面的量測是動手時先量的）

1. 舊的不動：黃金雜湊；`tests/machine-gun2.mjs` 群組 `old`；`tests/hill-map.mjs`；全部既有守衛綠。
2. 旗標：第 0 步的 `map` 帶 `sym: 1` → `w.sym = 1`；第 1 步以後的不理；雜湊跟沒帶的不同；指令檢查收它、不收 `sym: 'x'`。
3. 編隊：第 0–8 台，左上那一方的偏移是右下那一方的負號；沒有旗標時兩邊一樣（舊規則）。
4. 尋路：在點對稱的丘陵上，從很多對 (A, B) 找路，開旗標時從 A 的鏡像到 B 的鏡像的路＝A 到 B 那條路的鏡像（全部）；沒開旗標時有不一樣的（守衛裡當對照）。
5. 指揮部、出生格、集結點：丘陵開旗標時，左上那一方的指揮部、第一班步兵的出生格與集結點，都是右下那一方的鏡像；沒開時不全是。
6. 量測：上面那張表用 50 個種子重量寫進驗收結果（不設門檻：村莊與萊伊的地圖本身不對稱）。
7. 新開的局送 `sym: 1`、`?noR084=1` 不送（真的 Chrome）。
8. 每一條守衛故意弄壞一次，第一個紅燈落在它身上。
9. README、LOG、路線圖；`main.ts` ≤ 673、`battle.ts` ≤ 1195。
