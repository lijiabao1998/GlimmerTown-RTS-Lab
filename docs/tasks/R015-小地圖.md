## 為什麼做這張

手機上一次只看得到戰場的一小塊：敵人從哪邊來、自己的車散在哪、榴彈砲在打哪一區，都要拖來拖去才知道。RTS 的小地圖是最基本的全局資訊，也是手機上最快的移動鏡頭方式。

## 做什麼（只改介面）

1. **小地圖**：畫面右上（按鈕列下面）一張菱形小地圖，方向跟主畫面一樣（斜 45°、上下壓扁一半），用 DOM 的 2D 畫布畫（不加 WebGL 繪製呼叫）：地形（路、草、田）、還站著的建築、瓦礫、彈坑、我方單位藍點、**看得到的**敵方單位紅點（R100）、目前畫面看得到的範圍（白框）。
2. **點小地圖**：鏡頭滑到那一點（有 R012 就 0.4 秒平滑，`?noR012=1` 時直接跳過去）。
3. 布陣時也在；手機 412×860 不擋按鈕、不擋布陣列與提示列。
4. 純邏輯（地圖格 ↔ 小地圖座標、要畫哪些點）放在 `src/ui/minimap.ts` 的純函式，Node 可以測。
5. **逃生閥** `?noR015=1`：沒有小地圖；雜湊不變。

## 不改什麼

- 不改 `src/sim`、`src/render`、黃金雜湊、指令格式；不改主畫面的鏡頭角度與縮放範圍；不調高手機預算。

## 驗收（動手前寫）

1. `npm run check` 本機與 CI 全綠；黃金雜湊不變；Node＝Chrome；繪製呼叫與三角形跟 main 相同（小地圖是 DOM 畫布）。
2. Node 守衛 `tests/minimap.mjs`：地圖格 → 小地圖座標 → 地圖格來回誤差 < 0.01 格；地圖四個角落在畫布內；主畫面的「右」與「上」在小地圖上也是右與上；點的清單：我方全部活著的單位、敵方只有看得到的（看不到的不出現）、死掉的不出現；`?noR015` 時沒有小地圖。
3. 煙霧測試（手機，真觸控）：小地圖在畫面內、不跟按鈕列／布陣列／提示列重疊；點小地圖上某一格的位置，0.6 秒後鏡頭中心在那一格附近（< 1 格）；拍 `mobile-minimap.png`；`?noR015=1` 沒有小地圖、雜湊不變；既有觸控測試照舊。
4. 每條新守衛故意弄壞一次，第一個紅燈落在它身上（記在卡面）。
5. 看樣張，卡面寫看到什麼。
