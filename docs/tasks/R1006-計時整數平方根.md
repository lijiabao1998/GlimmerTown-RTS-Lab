## 為什麼做這張

R1002 的驗收 30 沒過：每邊多 8 組工兵和火焰噴射器的大局，每一步的 p99 比同樣人數的步兵班貴 15–20%（R1003 補量 1.20、1.146 倍），門檻是 1.1 倍。R1002 卡面記的剖析是「看不看得到」（`spotted`）多 260 毫秒、火焰噴射器找目標（`aimFlame`）233 毫秒。

這一輪（2026-11-21）重新剖析同一個場景（`node --cpu-prof`，3,000 步，兩邊各跑一次）：

- 火焰噴射器找目標被叫了 23,992 次，**一次都沒找到目標、一次都沒叫到「看不看得到」**。它的 274 毫秒全花在「把全場每個敵人的距離都開一次根號」上：火焰的射程只有 2 格，全場九十個單位裡幾乎都在射程外。
- 整局最貴的不是新兵種，是所有兵種共用的找目標（`pickAim`，自身時間 1,805 毫秒，佔一步的一半以上），裡面幾乎都是內聯進去的整數平方根 `isqrt`。
- `isqrt` 用牛頓法從 n 本身開始往下逼：n 約一億（四十格左右的距離）時要先對半砍十幾次才接近答案，每次兩個除法。

所以這張不碰規則，只讓同樣的答案算得快一點：平方根的起點放到答案附近，火焰噴射器（和同樣寫法的狙擊手、反戰車小組）先用一個方框把一定打不到的單位排掉，不開根號。

## 做什麼

1. **`isqrt` 的起點**（`src/sim/math.ts`）：n < 2^32 時，起點取「比 √n 大的最小的二的次方」：`1 << ((33 - Math.clz32(n)) >> 1)`（`clz32` 在模擬層的白名單裡）；n ≥ 2^32 照舊從 n 起算。牛頓法的迴圈不改。
   - 為什麼結果一樣：整數牛頓法只要起點 x₀ ≥ ⌊√n⌋，就會一路往下收斂到 ⌊√n⌋ 然後停住；舊的起點 n 和新的起點都滿足這個條件，答案都是 ⌊√n⌋。新起點 x₀ 滿足 x₀² > n（n 的位數 b，x₀ = 2^⌈b/2⌉，n < 2^b ≤ x₀²），所以第一步一定往下走，迴圈的判斷不用改。
2. **火焰噴射器、狙擊手、反戰車小組找目標先框再算**（`src/sim/engineer1002.ts` 的 `aimFlame`、`src/sim/support91.ts` 的 `aim91`）：開根號之前先看 x、z 方向的差，有一個超過射程就跳過。
   - 為什麼結果一樣：|dx| > 射程時 dx² + dz² ≥ dx² > 射程²，⌊√⌋ 也 > 射程，原本那一行本來就會跳過它；框內的照舊開根號、照舊比最小射程、照舊排序。
3. **大家共用的 `pickAim` 迴圈不改**：那四行被 `tests/transport92-negative.mjs` 逐字錨住（`rider_aim`），中間插不進一行；它只吃第 1 點平方根變快的好處。
4. **守衛** `tests/timing1006.mjs`（新，Node）：
   - 平方根：0 到 2^22 每一個數、2^22 到 2^40 的每一個完全平方數前後各一、再加 20 萬個決定性抽樣（自己的線性同餘，不碰 `World.rng`），新舊兩個寫法逐一相等；舊寫法照抄在守衛裡當對照。
   - 方框：火焰噴射器正東、正北剛好在射程上（距離＝射程）的目標照樣被挑到；在射程外一個位置單位的照樣不挑；狙擊手同樣。
   - 整局逐位相同：四個局（R1002 計時場景帶 `sw`＝2、喪屍、海斯鎮、標準村莊帶補給），每 250 步算一次世界雜湊，跟改之前在 main `5b9fc66` 上量到、寫死在守衛裡的數字比。
5. **計時** `tools/r1002-time.mjs --check`（不進 CI；照 R1002 的量法：兩邊輪流各 5 次、取 p99 的中位數）。

## 不改什麼

- 規則、數字、指令、存檔、畫面一個都不改；黃金雜湊 `eea1d59b` 不變；舊的重播逐位相同。
- `pickAim`、`spotted` 的迴圈不改（錨住的行、而且不是這次量到的大頭）。
- 不加閥：沒有新效果；萬一結果不同，守衛的整局雜湊會紅。

## 驗收（動手前寫）

1. `tests/timing1006.mjs` 的平方根群：0…2^22 全部、2^22…2^40 每個完全平方數 k² 的 k²−1、k²、k²+1（k 每隔 97 取一個，加上 2^20 本身）、20 萬個抽樣，新舊相等。
2. 方框群：火焰噴射器的目標在正東、正西、正北、正南剛好射程上時被挑到；射程外 1 個位置單位不挑；狙擊手、反戰車小組同樣（各用自己的射程）。
3. 整局群：四個局各 1,500 步，每 250 步的雜湊跟 main `5b9fc66` 量到的逐一相同（數字寫死在守衛裡，旁邊註明量的提交）。
4. `npm run unit` 的內建段落（`UNIT_SHARD=1/200 node tools/unit.mjs`）：模擬層純度、黃金雜湊 `eea1d59b`、`isqrt` 抽樣，全綠。
5. 故意弄壞（隔離副本，手動跑一次、結果寫進施工紀錄），每一處守衛都要紅：
   - 起點改成 `1 << ((32 - Math.clz32(n)) >> 1)`（可能比 √n 小）→ 平方根群紅；
   - 起點改成 `1 << ((33 - Math.clz32(n)) >> 1) - 1`；
   - 方框用 `>=`（剛好在射程上的被排掉）→ 方框群紅；
   - 方框只看 x 不看 z、或 x、z 寫反（只要結果不同就要紅）；
   - `aim91` 的方框用火焰的射程（2 格）→ 方框群紅。
6. `node tools/r1002-time.mjs --check`：p99 比值 ≤ 1.1（機器忙時只記錄，不當成過不過；量之前確認沒有別的工作階段的無頭瀏覽器在跑，`tools/bench/` 沒有就看工作管理員）。
7. 整體快了多少：同一個 R1002 計時場景（只有工兵和火焰噴射器那一邊）改前改後各 5 次，記每一步平均與 p99；另記 `isqrt` 單獨的速度（一百萬次）。只記錄，不設門檻。
8. CI 全綠（含 `smoke`、瀏覽器分片）。
