## 為什麼做這張

三輛坦克一起下移動指令、或一起追同一個敵人，最後會疊成一輛；敵我坦克也能穿過彼此。畫面上看起來像少了兩輛車，也讓「擋路」「卡位」這些戰術不存在。

## 做什麼（模擬）

1. `UNIT_KINDS` 每種單位加 `radius`（位置單位）：坦克、榴彈砲是車輛；觀測員是步兵。
2. 每一步在「全部單位移動」之後、「全部單位開火」之前，做一次**整數推擠**：活著的車輛兩兩檢查，中心距離小於兩者半徑和就沿連線推開。
   - 先算完所有推擠量再一起套用（跟處理順序無關）；距離為 0 時用兩者 id 決定方向（決定性）。
   - 每一步每個單位最多被推半個車速以內（軟推擠）：正在走的車永遠比推擠快，窄巷對向也擠得過去，不會卡死。
   - **架好的榴彈砲不被推**（間接射擊、沒有在走的路）：被推會讓 R102 的試射校準重來；推擠全部算在另一方。兩門架好的砲互相重疊時照常互推。
   - 推擠不准把車推進還站著的建築格、不准推出地圖；某一軸會撞就只推另一軸，兩軸都撞就不推。
   - 觀測員（步兵）不參與碰撞；死掉的單位（殘骸）不參與碰撞。
3. 沒有新狀態：推擠每一步從位置重算，世界雜湊的欄位不變。指令格式不變，舊紀錄照樣重播（結果會因為碰撞而不同，黃金雜湊照實更新）。
4. 新守衛 `tests/collision.mjs`。

## 不改什麼

- 不改 A*（路徑不知道其他單位）、不改指令格式、不改射擊與傷害。
- 不改渲染、不加效果（沒有新的畫面效果，所以沒有逃生閥）。
- 不調其他數值。

## 驗收（動手前寫）

距離、時間全部從 `UNIT_KINDS`（`radius`、`speed`）推，不寫死。

1. 三輛坦克下到同一格的移動指令、六輛坦克疊在同一點出生：走完或靜止足夠久之後，任兩輛中心距離 ≥ 兩者半徑和 − 2。
2. 推擠從不把單位推進還站著的建築格或地圖外：200 個固定種子的隨機場景（建築、單位、指令）各跑 300 步，每一步檢查。
3. 窄巷對向：兩棟長建築夾出一格寬的巷子，兩輛坦克從兩頭對開，兩輛都在「沒有碰撞時所需時間」的 3 倍以內到達。
4. 架好的榴彈砲（已有試射校準 `seen > 0`）：一輛坦克的路徑直接穿過它，砲的位置一個單位都不變、校準 `seen` 不被重設。
5. 觀測員不碰撞：觀測員與坦克可以站在同一點；進駐建築的觀測員不受影響。殘骸不擋路：活著的坦克可以停在殘骸上。
6. 決定性：碰撞很多的場景，同指令跑兩次相同；指令紀錄 JSON 來回重播相同；中途 `structuredClone` 接著跑相同。
7. 黃金雜湊照實更新：卡頭寫 `fe1c5774→新`，卡面寫為什麼變；`npm run check` 本機與 CI 全綠；Node＝Chrome；手機預算不變。
8. 每條守衛故意弄壞一次，第一個紅燈落在它身上（記在卡面）。
