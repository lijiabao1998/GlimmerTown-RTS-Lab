## 為什麼做這張

業主 2026-11-16：「带建筑物破坏的红警」。現在一棟房子從完好到瓦礫，畫面上只有三個樣子：完好（耐久還剩七成以上都一樣）、沒屋頂的空殼（R138）、瓦礫；兩個階段之間挨幾發都看不出來，屋頂是一幀之內不見，倒塌是整棟一個殘影（R004）。玩家看不出「這棟還能撐多久」，也沒有「被打爛的過程」。

設計先跑了一個工作流（先派三個人讀模擬、畫面、玩法，再三份互相競爭的方案＋裁判）：
- 「只改畫面」：照現有的耐久多分幾段樣子，模擬一行不動。
- 「分段倒塌」：一棟房子一格一格倒（模擬改十五處左右，跟 R089 的大步兵班、R050 的建造衝突）。
- 「打穿的洞改變戰法」：洞讓屋裡的人能被直射、掩護分方向（玩法最有意思，但要改火力與掩護的熱點行，數字一合併就凍結，平衡還沒量）。

裁判選「只改畫面」當底子，嫁接另外兩份的好點子（分兩段倒下時往外倒、殘影＝整鎮網格裡那一段；洞的畫法與「洞只畫在看得到的面」）；「打穿的洞改變戰法」排在 R089 之後另開一張，它會直接用這張的洞的畫法。這張是美術卡（AGENTS §3.5：玩法與美術分開）。

裁判量到：現在 96 圖整鎮重建一次 46.8 毫秒（萊伊 9.8）；多分幾段之後，一局裡要重建整鎮的步數多一倍（萊伊 11 → 23、64 12 → 30、96 21 → 46）。所以這張要先做「每棟一份快取」，重建時只重算變了的那一棟。

## 做什麼

**一定要做**

1. **損壞的段**（`wearTier`，整數算，`lost = maxHp − hp`，比的時候寫成 `lost × 100` 對 `maxHp × k`）：

   | 段 | 條件 | 樣子 |
   |---|---|---|
   | T0 | 少於 5% | 跟今天一模一樣（逐位元） |
   | T1 | 5–13% | 小洞、掉幾片瓦 |
   | T2 | 14–21% | 大一點的洞、掉更多瓦 |
   | T3 | 22% 到變空殼之前 | 屋頂一角塌下去 |
   | T4 | 空殼、少於 65% | 今天的空殼，不變 |
   | T5 | 空殼、65% 以上 | 空殼塌一半 |
   | 瓦礫 | 耐久 0 | 今天的瓦礫 |

   模擬裡建築的耐久只會往下掉，所以段只會往後走。
2. **牆上的洞與屋頂的缺口**（T1、T2；R138 的五種民房，只在 +x、+z 兩面）：洞是暗色的洞口加四塊崩掉的邊（小 0.16×0.13、大 0.32×0.26，大的只在寬 ≥ 2 格的面）；屋頂一塊掉了瓦、露出椽子；一道裂縫；打破的窗。位置用 `hash2(b.id, k, 88)`，離牆面 0.02，不壓門窗。畫洞的函式收一串「打在哪裡」（可以不給），之後打穿的洞那張卡用它。
3. **屋頂塌一角**（T3）：只移動既有的頂點（不加三角形）——屋脊的一頭往下 0.55 倍的屋頂高、簷角最多往下 0.12；沒有頂點往上；法線重算；煙囪跟著屋頂。
4. **空殼塌一半**（T5）：鏡頭那一側由 `hash2` 挑的一半，0.25 倍牆高以上的頂點照 `y' = 0.25h + (y − 0.25h) × 0.35` 壓下去（牆頂從約 0.72h 變約 0.41h）；R138 的空殼與舊的空殼都適用；多兩堆碎磚、一根倒下的梁。
5. **屋頂塌進去**：完好變空殼那一刻，屋頂（簷以上的三角形）變成殘影，1.1 秒內往下沉（屋頂高 + 0.35）；今天是一幀之內不見。R004 的碎片與火照舊。
6. **分兩段倒下**：變瓦礫那一刻，那一段的幾何照三角形中心分成兩半——弱的那一半（T5 塌的那一半；完好就倒的是上半）先倒、另一半晚 0.22 秒；每一半 1.1 秒、往建築中心外倒；另外加 6 團煙、6 塊碎片。
7. **換段的效果**：只在看得到的地方，3 團煙（1.6–2.2 秒）、4 塊碎片（2.2–3.2 秒），用屋頂或牆的顏色；`?noR004=1` 或 `?fx=off` 時沒有。
8. **整鎮每棟一份快取**：重建整鎮時只重算變了的那一棟（鍵：種類、位置、大小、層數、耐久上限、階段、段、遠近層級、所有畫面模組的開關）。
9. **彈痕**：牆塌下去之後，沒有 R014 的彈痕留在牆頂上面的半空中。
10. **閥、守衛、開關對照圖、文件。**

**做得完才做**：R087 的三種新房型只做第 3、4 條（不畫洞）；指揮部只做第 3 條與帆布破口；T3、T5 時一聲崩塌（`audio.ts`，同一個閥）。

**這張不做**：遠景（96 圖的兩個遠近層級）照今天的階段畫；碉堡、圍牆、鐵絲網不變。

## 風險（先寫下來）

- 96 圖一整個地區的三角形被洞推過 14,000，提早換到遠景：先量；要修就讓洞的三角形不算進第 387 行的計數（沒有守衛錨著）。
- 屋頂塌一角看起來不對（外牆被拉長、煙囪浮在半空）：整區一起移、0.12 的上限、驗收第 7 條。
- 洞不在真的打到的地方（用雜湊挑看得到的面上的位置）：打穿的洞那張卡修。
- 戰爭迷霧多漏一點資訊（看得到的樣子從三種變六種，跟今天的階段一樣會漏）。
- 手機記憶體：96 圖快取約 8 MB。
- `battle.ts` 只剩大約 3 行。

## 驗收（動手前寫）

1. **卡面先**：第一個提交只有這張卡；`git diff ef73514 -- src/sim` 是空的；黃金雜湊 `eea1d59b`（Node 與 Chrome）。
2. **段**：`wearTier` 對耐久上限 60–1200 的每一個值、每一個耐久都測；耐久往下掉段不會往回；T4、T5 只在 `stageOf` 是空殼時出現；兩個新檔裡沒有 `Math.random`、`Date`、`performance.now`。
3. **T0 一模一樣**：R088 開著時，每一棟滿耐久的建築的位置、法線、顏色位元組跟 `?noR088=1` 一樣；地圖 0–4、`more` 開關、R086／R087／R120／R138 各自開關都測。
4. **閥關著**：跟在 `ef73514`（動手之前）凍結的指紋逐位一樣：`buildTown` 三個遠近層級、殘影數與頂點、特效池的內容、煙霧測試倒塌近景的 `fxDigest`。
5. **快取等於不快取**：在複製的世界上，用雜湊決定 300 次耐久的改寫，快取的 `buildTown` 跟不快取的逐位一樣（每一個遠近層級、帶 skip 的）；換一個模組開關、原地改種類／層數／耐久上限、`structuredClone` 的世界都不會拿到舊的。
6. **只讀、純函式**：建畫面與同步之後世界的 JSON、亂數、`hashWorld` 不變；`decodeWorld` 讀回來的世界、重播中途跳到某一步，畫出來的位元組跟一路打過來的同一步一樣；跑兩次一樣。
7. **幾何沒問題**：每個頂點都是有限值、法線長度 1、沒有退化的三角形；都在佔地裡、y ≥ 0；−x、−z 面上沒有洞的顏色；洞在那一面的範圍 ±0.02 內、在那裡的牆頂以下、不壓門窗；每棟最多多 64 個三角形；移動頂點不多三角形、沒有頂點往上。
8. **殘影**：每一半＝那一棟在那一段的整鎮網格裡的那一段；完好變空殼的下一幀有屋頂的殘影；變瓦礫的那一幀有兩個殘影、第二個晚 0.22 秒、都往外倒。
9. **彈痕**：T3、T5 之後，沒有活著的 R014 彈痕高過那個位置的新牆頂；R139 照舊（瓦礫上沒有彈痕）。
10. **效果**：跑兩次 `fxDigest` 一樣；`?fx=off`、`?noR004=1` 時特效池是 0、段的幾何照畫。
11. **手機開局**（412×860）地圖 0–4：繪製次數與三角形開關兩邊一樣，≤ 20 次、80,000。96 圖同一個遠近層級。
12. **近景**：萊伊用 `fireAt` 打到 T3、再打到 T5（步數在 Node 先算好）；桌機與手機 ≤ 22 次、80,000，繪製次數跟 `?noR088=1` 一樣；既有的倒塌近景照樣過。
13. **96 圖的地區**：標準鏡頭那一區的每一棟都打到 T3，跟 `?noR088=1` 同一個遠近層級，不然把數字寫在卡面。
14. **重建的時間**（Node、96 圖、同一次跑）：改一棟的段之後，快取的重建中位數 ≤ 不快取的 0.25 倍；兩個數字寫在卡面。
15. **故意弄壞**：至少 12 處，在隔離副本裡、各紅在指定的斷言上（逾時或語法錯不算）：小數的段、亂數的段、T0 畫了洞、洞在佔地外、洞在看不見的面、快取的鍵少一樣、快取不看模組開關、殘影用了現在的段、幾何用了「顯示的段」、彈痕沒有降、同步時動了 `w.rng`、閥沒作用。
16. **收尾**：總機行數、`tests/valves.mjs`、README 的閥那一列、`npm run check`、最新提交的整套 CI 都綠；真的 Chromium 在桌機與手機同一個鏡頭，住宅、穀倉、教堂從 T0 到瓦礫、開與 `?noR088=1` 的對照圖附在卡面，每一張寫看得到什麼。
