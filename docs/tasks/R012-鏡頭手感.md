## 為什麼做這張

手機上最常做的事是移動鏡頭。現在雙指捏合與滾輪都是對著畫面中心縮放——想放大看手指下的那棟房子，放大完它就跑出畫面；拖曳一放手就硬停，滑長距離要拖很多次。這是「操作起來順不順」的第一印象（R003 手感門檻）。

## 做什麼（只改鏡頭與輸入，不改模擬）

1. **縮放對準手指／游標**：滾輪縮放時游標下的地面點不動；雙指捏合時兩指中點下的地面點不動（縮放範圍照舊 0.55–3）。
2. **拖曳慣性**：單指拖曳放手時帶著最後的速度繼續滑，約 0.5 秒內停下；碰到地圖邊就停在邊上。按下去任何一指立刻停。
3. **雙擊我方單位**：鏡頭在 0.4 秒內平移到那台車（同時照舊選取它）。
4. 純邏輯放在 `src/ui/camera.ts`（慣性衰減、平滑移動的數學，不碰 DOM），Node 可以測。
5. **逃生閥** `?noR012=1`：回到 R011 的鏡頭行為；雜湊不變。

## 不改什麼

- 不改 `src/sim`、黃金雜湊、指令格式；不改鏡頭角度、不讓鏡頭旋轉、不改縮放範圍；不改點選規則（點一下＝選取／下指令）；不改畫風、後製、光；不調高手機預算。

## 驗收（動手前寫）

1. `npm run check` 本機與 CI 全綠；黃金雜湊不變；Node＝Chrome。
2. Node 守衛 `tests/camera.mjs`：
   - 對任一點縮放（放大與縮小、畫面四角與中心），縮放前後那一點下的地面座標相同（誤差 < 0.01 格）；縮放值照舊夾在 0.55–3。
   - 慣性：放手速度 v，之後每幀位移遞減、0.6 秒內停下、總滑行距離介於 0.1v 與 0.3v 之間（每秒格數）；按下立刻歸零；不超出地圖邊界。
   - 平滑移動：0.4 秒後到達目標（誤差 < 0.01 格），中途單調接近。
3. 煙霧測試（真的輸入事件）：桌機滾輪在畫面右上角放大，游標下的地面格不變；手機單指快速拖曳後放手，0.3 秒後鏡頭仍在往同方向移動、1 秒後停住；手機雙擊我方坦克，0.6 秒後鏡頭中心在那台車附近（< 0.5 格）、而且選到它；`?noR012=1` 時放手立刻停、雜湊不變；既有的觸控測試（點選、移動、點屋頂開火）照舊通過。
4. 每條新守衛故意弄壞一次，第一個紅燈落在它身上（記在卡面）。
