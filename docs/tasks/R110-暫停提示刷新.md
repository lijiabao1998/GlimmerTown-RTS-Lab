# R110［待辦 20］暫停時清除過期砲擊提示
<!-- card: sim=no; golden=無; valve=無; owner_ok= -->

## 為什麼做
R109 的砲擊選單會顯示成功或無合法砲種的提示。PR #38 審查發現普通命令只清掉內部提示，暫停時 HUD 每秒刷新不會前進，舊提示持續留在畫面，誤導玩家以為新命令仍是煙幕。來源：https://github.com/lijiabao1998/GlimmerTown-RTS-Lab/pull/38#discussion_r4308782203 。獨立 source＋真實 Hud.frame／DOM stub 重現 8 個案例，其中 7 個在暫停 120 幀後仍留舊字；友方點選已有刷新。

## 做什麼
以一個共用清除提示函式同步清狀態與 HUD，涵蓋普通 order、tap 與 clearGestureInput。補暫停回歸守衛和 production-source 負控制，CI 真實 Chrome 補驗普通觸控下令與取消後的文字更新。

## 不改什麼
不改模擬、命令格式／內容／次數、golden、AI、步兵、武器數值、選取及鏡頭手勢、工具列模式、畫面樣式、預算或受保護路徑。不是新視覺效果，無新增逃生閥；既有 ?noR109=1 仍關閉選單與快捷手勢，不改雜湊。保留既有 Hud.frame 按模擬秒更新的方式，不改成每幀重繪。

## 驗收（動手前寫）
1. 暫停且模擬 tick 不前進時，成功／錯誤砲擊提示之後，普通右鍵 order 或地面／敵人／房屋 tap 立即清掉畫面舊提示；清完走原 HUD 模式與選取說明。不能靠跨過下一個模擬秒才更新，120 次 Hud.frame 仍須正確。
2. 沒選單位、無地面、煙幕模式但無合法榴彈砲等無路由早退同樣清字、不發命令。友方點選、Shift 切選與原本的命令 payload／次數不變；對照固定 fixture 的 move／attack／fireAt 獨立預期，hash／RNG 不變。
3. clearGestureInput 在選單已關閉時仍清字，取消、失焦、resize、active lost capture、外部／小地圖 pointerdown 等既有呼叫可立即刷新；原手勢取消行為保留。不改正常長按放手保持選單、工具列狀態與關閉 ?noR109=1 的原操作。
4. 共用清除函式沒有提示時不多一次 HUD update；首次 HUD 尚未建立的初始化安全。只在輸入清理時更新，Hud.frame 節流不變，沒有每幀新增 DOM 或 WebGL 工作。
5. tests/*.mjs 新守衛讀真實 production handlers 與 initHud，DOM stub 只模擬所用 API，不自製另一份 HUD 邏輯；每組隔離 production-source 負控制第一個紅燈必須是相應語義斷言，語法／載入錯誤不算。既有手勢／煙幕／命令守衛與門檻不削弱。獨立審查最小修補與回歸範圍。
6. CI 真實 Chrome 以 touch 長按產生提示，暫停不推進 tick，接著普通 touch 下令／取消事件，驗證提示立即消失且命令精確不變；隔離暫存 mutant bundle 移除刷新時同一斷言紅，沒有出貨測試開關。保留每支 unit 120 秒上限。完整 typecheck／unit／build／smoke 與 main 版 lane 據實記錄；本機 Chrome 受限照實寫未跑，CI 不略過。
7. 不改 src/sim 或 golden；原 SCRIPT 600／1200 tick 仍 c789deeb／f3364bb6，Node＝Chrome、重播／clone 仍過。查看最新 CI 四圖與提示修補特寫，手機開局 ≤20 calls／80,000 triangles、戰鬥 ≤22／80,000。最新提交 CI smoke／gpt-lane 與合後 main／Pages 綠才完成；不宣稱 Android 實機。
