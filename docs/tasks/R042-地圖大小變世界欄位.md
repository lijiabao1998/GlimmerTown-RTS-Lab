## 為什麼做這張

- 地圖邊長是 `src/sim/world.ts` 的常數 `N = 32`。`src/` 裡有 125 行用到它，分在 21 個檔；格索引 `idx(x, z) = z * N + x`、`inMap(x, z)` 也寫死 32。
- 大地圖（R043）要 64×64。不先把「地圖多大」變成每個世界自己的欄位，大地圖做不出來。
- 這張只搬家、不改行為：32×32 的局逐位相同，黃金雜湊不變。路線圖 R025 的前半就是這件事（R017、R038）。

## 做什麼

1. `src/sim/world.ts`：
   - `World.n` 已經有，維持 `createWorld` 給 32。
   - 新增看世界的幫手：`cellIdx(w, x, z)`（`z * w.n + x`）、`inGrid(w, x, z)`、`gridLimit(w)`（`w.n * SUB - 1`）。名字可以照實作調整，卡面寫清楚。
   - 舊的 `N`、`idx`、`inMap` 留著、意思不變（32×32 舊局專用），註解寫明 `src/` 不再用；`tests/` 裡 28 支舊守衛照樣能 import。
2. `src/sim/*`、`src/render/*`、`src/ui/*`、`src/main.ts`：所有看地圖大小的地方改看世界：
   - 格索引、邊界、夾值、`c % N` 這種反算座標；
   - `path.ts` 的堆積鍵 `K = N * N`；
   - `counterbattery.ts` 的分區數 `N / ZONE_CELLS`；
   - `build.ts` 的半場 `territory()`（要知道地圖多大）、`eco.ts` 的角落與中線、`smoke.ts` 與 `step.ts` 的夾值；

   - 小地圖、指令選單、提示裡的邊界。
3. `BattleView.setWorld(w)` 換到不同大小的世界時，重新配置所有跟大小有關的緩衝，不能沿用舊大小（R043 的 `map` 指令會在第 0 步換大小）。

     - 尋路走得到 x、z > 32 的格；

## CI 首紅與修補（PR #70）

- **紅在哪**：run 39939010050 的 `unit (1/4)`、`unit (2/4)`，分別是 `tests/audio-browser.mjs`、`tests/vegetation-browser.mjs`，訊息都是 `ReferenceError: N is not defined`。
- **原因**：這兩支會把自己的場景建構函式（R117 的音效場景、R116 的林地場景與地形差異診斷）嵌進隔離建置的 `main.ts`，裡面用到 `N`。`main.ts` 不再 import `N` 之後，嵌進去的那幾行在頁面裡找不到它。瀏覽器守衛本機沒跑，所以施工時沒抓到。
- **改法**：嵌入程式裡的 `N` 換成同一個世界的 `w.n`。
  - `audio-browser` 1 處；`vegetation-browser` 4 處，分在 `forestFixture` 與 `terrainDifference`。
  - 只在 Node 端跑的那幾處照用 import 的 `N`。
  - 斷言、預期值、訊息都沒動。
- **本機驗證**：
  - `audio-browser` 退出碼 0。
  - `vegetation-browser` 不再出現 ReferenceError，但跑到它自己的時限就停了（R116 browser operational deadline exceeded）。那時同一台機器上另外兩條線的代理也開著 Chrome，負載 12（4 核），是環境的慢，以 CI 為準。
