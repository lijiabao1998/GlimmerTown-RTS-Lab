# R148　手機左側的全排與搭車（待辦 48）
<!-- card: sim=no; golden=無; valve=?noR901; owner_ok=業主指定接在待辦 45 後面 -->

## 為什麼做

步兵旁有空車時，「全排」和「搭車」會一起出現。兩顆按鍵原本往畫面中央伸出，手指在戰場選點時很容易碰到。

## 做什麼

直式手機的左側指令列上方放「全排」、下方放「搭車」。兩鍵與相鄰的工具開關保有獨立觸控範圍，使用不同高度的手機都能選到。

## 不改什麼

沿用原本的顯示資格、選取規則、橫向排列與桌面快捷鍵。

## 驗收（動手前寫）

1. 360 和 412 像素寬的直式觸控視窗都能同時看到兩鍵，左緣對齊安全區，觸控面至少 44×44 CSS 像素、上下間距至少 4 像素，中心與內側四角皆可點。另測窄短畫面以及 860×412 橫向。
2. 在同一局選步兵班後，實際點「全排」選到三班，再點「搭車」把附近空車加入選取。切換工具、生產選單後兩鍵仍可操作；空選取會收起按鍵。
3. 新版面守衛在原來的排列會報錯。桌機 Chrome 的手機尺寸截圖由本機 NPU 做中文辨識；另遮住第二字做負對照，完整文字才可通過。
4. 完整 CI，包括原有的手機、空中鍵、運輸、步兵排與 smoke 守衛全綠，再合併。

## 施工紀錄

基線 `8d73b9f`。直式手機左側的第一格放「全排」，下一格放「搭車」。有其中一顆可用時，「具、產」移到右鄰，空選取會把這一欄還給地圖。新手教學打開時會讓出兩欄的位置。高度 700 像素以下的生產列讓出左邊一欄，生產選項仍可直接點。

原版兩鍵在 320×568 的左緣分別是 60、108 像素，新守衛在此處如期報錯。開發時也用 Chrome 觸控事件重現了工具鍵一直留在內側造成的問題。距「具」邊緣 6 像素的手指會被 Chrome 算到按鈕上，導致空選取時雙指縮放變成單指平移。修正後原有雙指縮放測試通過。

PR #170 首輪在 Ubuntu 的文泉驛字型重現 320×568「產」碰到第一顆坦克生產鍵。高度 700 像素以下改讓「具、產」左右並列，並實測新手教學與按鈕至少隔 16 像素。Windows 與 Linux Chrome 的七直一橫均重新通過。首輪 CI 的四張標準圖與 #169 對應的圖逐位元相同，開局與 30 秒的村鎮、工具列及小地圖完整。

## 驗收結果

- Windows Chrome 實際點選。直式 320×568、320×640、360×640、360×780、390×844、412×860、480×720 均為 44×44 CSS 像素，上下間距 6 像素。中心及四角都能點到各自按鈕。模擬左側 24 像素安全區時，兩顆左緣均為 24 像素。860×412 橫式保留原有橫列。
- 同一局由一班選到全排三班，再加入鄰近空車。收合工具、生產選單和重新打開新手教學後仍可操作。七張截圖均可讀到兩鍵。三種最短的尺寸另外核對展開的生產列與相鄰指令，每顆均可點，文字完整。
- 本機 Intel AI Boost 經 OpenVINO 指定 `NPU` 執行中文文字辨識。由七張截圖逐一讀出「全排、搭車」共 14 個詞。遮住每顆的第二字後，14 個對照只讀到第一字。CPU 對同一批截圖的辨識結果一致。
- 正式建置、型別與手機版面守衛通過，模擬黃金值為 `eea1d59b`。完整 Linux 分片及桌機、手機開局與 30 秒的標準樣張見 PR 的 CI 附件。

### 沒做成的事

手機尺寸及安全區使用桌面 Chrome 觸控模擬。NPU 驗的是已渲染的像素，按鍵命中與選取結果由真瀏覽器另驗。
