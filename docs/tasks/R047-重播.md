## 為什麼做這張

模擬從第一張卡起就是「種子＋指令紀錄＝整局重播」，但這件事只有守衛在用：玩家打完一局，那一局就沒了。打了一場漂亮的仗沒辦法再看一次，也沒辦法把它傳給別人；回報問題時也只能用嘴巴講。R046 之後每一局的設定更多（地圖、兵力、補給、種子），「再來同一局」更需要有東西留下來。

路線圖 R047 原本寫「存檔與重播」。這張只做**重播**（打完的局）。另外兩件事分開出卡，各自小而完整：

- 記住上次的遭遇戰設定（R069、R046 都留著沒做）→ 下一張。
- 打到一半存起來、下次接著打（「繼續上一局」）→ 再下一張；它存的是整個世界，跟重播存指令是兩套東西。

## 做什麼

### 1. 模擬：指令檢查（只加不改）

- 新檔 `src/sim/commandCheck.ts`：`isCommand(x)` 逐種指令檢查欄位的型別與範圍（整數、陣列長度上限、字串列舉）；`checkLog(log)` 檢查一份紀錄（每筆的 tick 是不往回走的非負整數、指令都合格、總筆數有上限）。
- 匯入別人給的紀錄之前一定先過這一關：`step()` 假設指令的形狀是對的（例如 `move` 一定有 `ids` 陣列），形狀不對會丟例外。
- 不改 `step()`、不改任何既有指令的意思。

### 2. 重播紀錄的格式（第 1 版）

```ts
{ v: 1, seed, ticks, hash, log, at, meta: { map, n, winner, seconds, wave? } }
```

- `ticks`、`hash`：存檔那一刻的步數與世界雜湊。重播跑到 `ticks` 時比對 `hash`，對得上才說「跟原局相同」。
- `at`：存檔時間（ISO 字串，只給人看）。`meta`：列表上顯示用（地圖、邊長、勝負、打了幾秒、喪屍撐到第幾波），不影響重播。
- 讀檔：不認得的欄位略過；`meta`、`at` 缺了照樣能讀；`v` 不是 1、`seed`／`ticks`／`log` 不合格就拒收並說原因。之後改格式就加版本號，第 1 版永遠要讀得進來。

### 3. 存

- 一局分出勝負的那一刻自動存一筆到本機（鍵名 `gtrts.v1.replays`），最新的在最前面，最多留 10 筆，超過丟最舊的。
- 沙盒不存（沒有勝負）。正在重播的那一局不再存一次。
- 本機存不了（隱私模式、空間滿）時不報錯，只是沒有紀錄。存壞掉的資料讀不出來時當作沒有，不讓頁面壞掉。

### 4. 看

- 開始選單多一顆「重播」。按進去是重播面板：列出存下來的局（勝負、地圖、打了多久、種子、時間），點一筆就從頭播。
- 播的時候：照原本的速度跑（⏸、1×／2×／4× 照舊可用），畫面上方一條「重播中」＋進度＋「離開」；點地圖不會下指令。
- 播到存檔那一步：比對雜湊。相同就照原局出戰報；不同就在那一條上寫「這份紀錄是別的版本存的，結果可能跟原局不同」（模擬改過數值的話，舊紀錄本來就會走出不同結果，這不是錯，但要說）。
- 「離開」或戰報的「再來一局」回到一般開局。

### 5. 匯出、匯入

- 重播面板每一筆旁邊有「匯出」：下載一個 `.json` 檔（內容就是上面的格式）。
- 面板有「匯入」：選一個 `.json` 檔；通過檢查就加進列表最前面，不通過就在面板上寫原因，列表不變。

### 6. 接線與守衛

- 新檔 `src/sim/commandCheck.ts`、`src/ui/replayStore.ts`（格式、讀寫、本機儲存；不碰 DOM）、`src/ui/replay.ts`（面板、播放、匯出匯入）。`src/valves.ts` 加 `r047`。
- `src/main.ts`：一行 import、一行接線、`tick()` 裡取指令的那一行改成先問重播（正在重播就餵紀錄裡這一步的指令，並在分出勝負時存檔）。行數不超過 673。
- `tools/cdp.mjs`：`open()` 預設在開頁前清掉 `gtrts.v1.replays`（每次開頁都當成第一次來；同一個瀏覽器設定檔裡前一頁存的重播不會影響下一頁的守衛）；要測「存了之後再開頁還在」的守衛傳 `{ keep: true }`。`AGENTS.md` 第 3 節第 6 條寫明。
- 新守衛：`tests/replay.mjs`（不開瀏覽器）、`tests/replay-browser.mjs`（真 Chrome）。

## 驗收（動手前寫）

**格式與檢查（Node）**

1. `isCommand`：目前遊戲會記進紀錄的每一種指令（`map`、`rules`、`zombies`、`build`、`trench`、`eco`、`ai`、`produce`、`move`、`attack`、`fireAt` 含煙幕、`fireDiscipline`、`stop`、沙盒三種）各至少一個合格的例子通過；腳本戰鬥 `SCRIPT` 的每一筆都通過。
2. `isCommand` 拒收：不是物件、沒有 `t`、不認得的 `t`、`ids` 不是陣列或裡面不是整數或超過上限、座標不是整數、`ammo` 是別的字串、`hold` 不是布林值。每一種至少一個例子。拒收的東西丟給 `checkLog` 會得到說明是第幾筆的原因。
3. `checkLog` 拒收：不是陣列、tick 是負數或小數、tick 往回走、超過筆數上限。
4. 來回：真的跑一局（布陣、補給、電腦對手、R046 的規則都開）到分出勝負或 1,200 步，做成紀錄 → 轉成文字 → 讀回來 → 從頭重播到 `ticks`，雜湊等於紀錄裡的 `hash`。
5. 讀檔拒收並說原因：不是 JSON、`v` 是 2、缺 `seed`、`ticks` 是負數、`log` 裡有不合格的指令。多帶不認得的欄位、缺 `meta` 或 `at` 的第 1 版紀錄讀得進來。
6. 儲存（用假的 storage）：存 12 筆只留最新 10 筆、最新在前；同一局存兩次只有一筆；storage 裡是壞掉的字串時讀到空列表；storage 一碰就丟例外時讀寫都不丟例外。鍵名以 `gtrts.v1.` 開頭。
7. `isCommand` 與 `checkLog` 各故意弄壞一次（隔離副本），第一個紅燈落在自己的斷言上。

**遊戲裡（真 Chrome）**

8. 打完一局（守衛用小兵力加快），本機多一筆紀錄，`seed`、`ticks`、`hash` 等於那一刻的世界；開始選單有「重播」，面板列出這一筆。沙盒不產生紀錄。
9. 點那一筆：世界回到第 0 步重新跑；「重播中」那一條看得到；這時點地圖、按右鍵，紀錄以外的指令不會進世界（跑到 `ticks` 時雜湊等於紀錄的 `hash`）；跑到底那一條顯示跟原局相同，戰報照出；本機還是只有一筆（重播不會再存一次）。
10. 「離開」回到布陣第 0 步的一般開局；之後打的局照常會存。
11. 匯出得到的文字讀回來等於那一筆紀錄；把它存成檔案用「匯入」選進來，列表多一筆、可以播、雜湊對得上。匯入一個壞檔，面板寫出原因、列表不變、頁面零錯誤。
12. 拿一筆紀錄把 `hash` 改掉再匯入、播到底：那一條顯示「別的版本存的」那句話，不說相同。
13. 版面：重播面板在 1280×800、412×915、360×780、860×412，每顆鍵至少 44×44、整顆在畫面裡、中心點得到。
14. 逃生閥 `?noR047=1`：沒有「重播」鍵、打完不存、本機沒有 `gtrts.v1.replays`；黃金雜湊不變。
15. 故意弄壞至少三處：打完不存、播的時候玩家的指令漏進世界、雜湊不同卻說相同——各紅在自己的斷言上。
16. `main.ts` 行數不超過 673；全套 CI 綠；附手機與桌機的重播面板、重播中的樣張。

**跟「做什麼」不一樣的地方，與施工中修掉的問題：**

- **重播起播多做兩件事。**（重建畫面用的是畫面本來就有的 `recreate()`，跟沙盒重置同一條路。第一版多呼叫一次 `makeView()`，`tests/valves.mjs` 與 `tests/trenches-ui.mjs` 都要求 `main.ts` 裡它剛好兩處，所以不那樣寫。） 重播跟守衛的 `playLog` 一樣，從只有種子的空白世界開始；地圖、規則、布陣、指揮部都在第 0 步才落地。畫面如果照空白世界建，大地圖就會對不上。所以起播時先走第 0 步，再照落地後的世界重建畫面與戰報統計；大地圖把鏡頭對準我方角落。
- **「重播中」那一條的位置改由程式找。** 第一版寫死在上方中間，字會被擠成兩行；改到左上後，守衛量到 360 寬的手機（工具列排成兩排）會壓到狀態列，橫向手機會壓到開火鍵。最後不寫死：從左上往下、往右掃，放在第一個不碰到狀態列、工具列、小地圖、側邊鍵與其他按鈕的空位；視窗大小變了、字數變了就重找。那一條的字也從「重播中 0:12／0:57 · 不能下指令」縮成「重播中 0:12／0:57」。
- **按「再來一局」後那一條會留在畫面上。** 世界被換掉之後遊戲停在布陣、不再走步，`feed()` 等不到，沒有機會收掉。播放期間另外每 0.2 秒看一次世界有沒有被換掉。
- **列表上的時間原本顯示成世界協調時間**（比這裡慢 8 小時）。紀錄裡照舊存 ISO 字串，顯示時換成這台機器的當地時間。
- **重播面板的 id 原本用 `rp-` 開頭**，跟 R010 戰報的 `rp-look`、`rp-again` 同一個開頭，改成 `rpl-`。
- 卡面寫「面板有『匯入』：選一個 `.json` 檔」「每一筆旁邊有『匯出』」，照做。匯出的檔名是 `gtrts-replay-<種子>-<步數>.json`。

## 驗收結果

**格式與檢查**（`node tests/replay.mjs`，本機 Node 24.15）

1. 綠。16 種指令各有合格的例子（共 22 個），腳本戰鬥的 8 筆都通過。
2. 綠。32 個不合格的例子全部拒收（不是物件、沒有 `t`、不認得的 `t`、`ids` 不是陣列／有小數／有字串／超過 256 個、陣營不是 0 或 1、座標是小數／缺／太大／`NaN`、`ammo` 是 `'he'`、`hold` 是 1……）；剛好 256 個單位仍合格；多帶不認得的欄位仍合格。壞指令放進紀錄，`checkLog` 回「第 2 筆的指令格式不對」。
3. 綠。不是陣列、像陣列的物件、空的那一筆、步數是負數／小數／超過上限／往回走／沒給、超過 20 萬筆：都拒收。同一步有好幾筆指令是合格的。
4. 綠。萊伊、精簡、快補給、布陣一棟、補給全開、雙方交給電腦，跑到分出勝負或 1,200 步：做成紀錄 → 文字 → 讀回 → 重播，雜湊相同；換種子雜湊不同。存檔那一步才下、還沒套用的指令不進紀錄。
5. 綠。不是 JSON、陣列、`null`、`v` 是 2（原因裡有「版本」兩個字）、沒有種子、種子是負數或超過 32 位元、步數是負數／0／小數、雜湊不是 8 位十六進位、紀錄裡有壞指令（原因指到「第 1 筆」）、超過 100 萬字：都拒收並有原因。把任何一個欄位換成 5,000 層的巢狀陣列，都只會被拒收或改用預設值，不會丟例外。沒有 `meta` 與 `at`、多帶不認得欄位的第 1 版紀錄讀得進來；`meta` 裡亂填的東西改用預設值，不拒收。
6. 綠。存 12 筆留最新 10 筆、最新在前；同一局再存一次是移到最前面，不是多一筆；壞掉的字串讀成空列表；列表裡壞的單筆略過、好的留著；一碰就丟例外的 storage、沒有 storage，讀寫都不丟例外；空間只放得下 3 筆時留最新 3 筆；完全寫不進去時回傳的是本機原本那幾筆（新的不在裡面）；六筆各四十幾萬字的紀錄只留得下最新三筆（總量 150 萬字以內）；單筆超過 100 萬字的不存。鍵名 `gtrts.v1.replays`。
7. 綠。隔離副本故意弄壞兩次，第一個紅燈各落在：
   - 不檢查 `ids` 裡面的東西 →「check: rejects {"t":"move","side":0,"ids":[1.5],"x":1,"z":1}」
   - 不擋步數往回走 →「log: rejects tick going backwards」

**遊戲裡**（`node tests/replay-browser.mjs`，真 Chrome；本機是無頭 Chrome＋軟體 WebGL，手機觸控 412×915）

8. 綠。打完一局（萊伊、精簡、沒有指揮部、雙方交給電腦，遊戲時間約一分鐘分出勝負），本機多一筆：種子、地圖、勝負等於那一局，步數與雜湊經 `playLog` 重跑對得上。重新開頁（`keep: true`）紀錄還在。開始選單有「重播」，面板列出這一筆。沙盒打 400 步不產生紀錄。

12. 綠。把紀錄的雜湊改掉放進本機再播到底：那一條顯示「這份紀錄是別的版本存的，結果可能跟原局不同」。
13. 綠。重播面板在 412×915、360×780、860×412、1280×800 沒有不合格的鍵。另外量了「重播中」那一條：這四個尺寸都不碰狀態列、工具列、手機側邊鍵、開火鍵、小地圖，「離開」至少 44×44、點得到。
14. 綠。`?noR047=1`：選單沒有「重播」、打完本機沒有 `gtrts.v1.replays`、腳本戰鬥雜湊 `eea1d59b`。
15. 綠。故意弄壞三處（只編進 broken 那一份）：
    - 打完不存 →「save: one record after the battle (found 0)」

**對抗式審查**（`docs/DECISIONS.md` 品質門檻第 6 條）

請一個沒看過我結論的審查代理只讀這個分支的差異與卡面。它拿各種「型別對、數值離譜」的指令（極大、負數、不存在的單位與種類、放錯世界的沙盒與喪屍指令）實際丟進 `runLog`，沒有一個丟例外；匯入的字串進畫面前都有跳脫；「遊戲裡開局」與「拿紀錄重播」在四張圖、有規則、喪屍共 10 種情況雜湊相同；`main.ts` 沒有初始化順序的問題。成立的有五項，已修：

1. **匯入檔把 `v` 寫成 5,000 層的巢狀陣列，檢查時把它轉成字串會爆堆疊，例外沒人接，面板不會顯示「匯入失敗」。** 原因句不再對任意值轉字串；整個檢查包在 try 裡，任何意外都回「讀不出來」；匯入那一串最後多接一個 catch。守衛：Node 對六個欄位各試一次 5,000 層巢狀；瀏覽器真的匯入一個這樣的檔。
2. **本機一直寫不進去時，`addReplay` 回傳空列表，面板卻寫「已匯入」。** 改成回傳本機真的存著的列表；匯入後找不到那一筆，就說「已匯入，但本機存不進去……關掉頁面就沒了」，這次開著的時候照樣可以看。
3. **沒有總容量上限。** 這個網域跟另外三條線共用本機空間。加上：單筆最多 100 萬字（匯入、自動存同一個上限）、全部最多 150 萬字、匯入前先看檔案大小再讀。
4. **看別人的喪屍重播，戰報會把自己的「最佳波數」改高。** 重播那一條顯示著的時候，戰報只讀最佳紀錄、不寫。
5. **守衛裡「同一局打兩次要一模一樣」會隨機器快慢飄。** 原本開戰、暫停、把我方交給電腦是三次分開的呼叫，中間畫面多跑一步，電腦接手的那一步就不同，結果也不同。改成同一次呼叫做完。另外兩句驗不到東西的斷言：一句拿掉，一句改成真的選了單位再點地圖。

屬實但沒有擋乾淨的（照實記）：

- **一份合格的紀錄可以讓重播非常慢。** 同一步塞很多條「移動」指令，每條都要替幾十個單位找路：審查量到 96×96 圖上同一步 40 條要 4 秒、500 條要 78 秒（機器當時很忙，絕對值偏大）。這擋不乾淨：玩家暫停時本來就能在同一步下很多指令，所以「每一步最多幾條」不能設得小，不然遊戲自己存的紀錄會被自己拒收。做了的只有把一條指令最多點的單位數從 1,024 降到 256、單筆上限降到 100 萬字。結果是：匯入來路不明的檔，最壞會讓那一頁卡很久，要關掉分頁；不會壞到本機的其他資料，也跑不了程式。



### 沒做成的事

- **打到一半的存檔（繼續上一局）沒做**，另出卡。重播只存分出勝負的局；打到一半關掉網頁，那一局就沒了。
- **記住上次的遭遇戰設定沒做**，另出卡。
- 沒在實機（Android、iPhone）上看。匯出靠瀏覽器下載、匯入靠選檔案，手機瀏覽器（尤其是 App 內嵌的）對這兩件事的支援不一，沒有實測；守衛是攔下要下載的內容、用除錯介面塞檔案。
- 匯入來路不明的檔，最壞會讓那一頁卡很久（同一步塞大量移動指令；見「對抗式審查」最後一段）。沒有擋乾淨，只收緊了上限。
- 沒有「分享連結」或複製到剪貼簿，只有檔案。
- 重播時不能拖時間軸、不能倒帶、不能換到敵方視角；只能從頭看，用原本的 1×／2×／4× 與暫停。戰爭迷霧照我方視角。
- 播放時生產列、開火鍵還在畫面上，按了沒反應（指令被擋掉），沒有把它們變灰。
- 紀錄綁模擬的版本：之後哪張卡改了數值或規則，舊紀錄播出來就會跟原局不同。這時只會顯示那一句提醒，沒有辦法照舊版規則播。
- 大地圖的守衛不是真的打到分出勝負（全滅要打很久），是打 400 步後自己照格式做一筆紀錄；「大地圖打完自動存」這一條路只由 32×32 的守衛驗。
- 最多留 10 筆，沒有讓玩家自己刪單筆或釘住不刪的功能。
- `open()` 預設清重播紀錄，是為了不讓前一頁影響下一頁的守衛；代價是「守衛預設看不到跨頁留下來的紀錄」，要測得明寫 `{ keep: true }`。
