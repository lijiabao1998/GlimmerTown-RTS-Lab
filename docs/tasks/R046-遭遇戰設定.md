## 為什麼做這張

路線圖從 2026-10-27 起把它列為下一張，它是 R048 戰役與 R050 建造的前置。北極星的評量標準有一條「每一局不一樣」：現在開局能選的只有地圖、模式、電腦難度（R069 開始選單做的）；雙方起手永遠是同一批兵、補給永遠每秒 +1、種子只能靠改網址。打過幾局之後，每一局的開頭都一樣。

R069 已經做掉的部分，這張不重做：
- 開始選單本身、地圖三選一（各自帶大小）、模式三選一、電腦難度三選一、「開始」。
- 路線圖寫的「模式選單把『地圖』『喪屍』兩顆鍵收進去」：R069 把布陣前四顆入口鍵（沙盒、地圖、喪屍、河鎮）都收進選單了。
- 守衛直接開局：`tools/cdp.mjs` 的 `open()` 預設帶 `noR069=1`，不經選單。

這張補上還缺的三項設定（兵力、補給速度、種子），加一張讓種子看得出差別的地圖。

## 做什麼

### 1. 模擬：一條新指令 `rules`（只加不改）

```ts
{ t: 'rules'; force?: number; income?: number }
```

- 只在第 0 步、還沒有指揮部（`eco`）、還沒進喪屍模式、不是沙盒時生效，而且只生效一次。`step()` 開頭的順序變成：地圖 → **規則** → 喪屍 → 布陣 → 其他指令。
- 狀態存在 `World.rules`，只在有值時折進雜湊（各欄位各自帶標記）。之後 G 段「專業戰爭模擬」每張卡的規則旗標（穿甲、士氣、彈藥……）都加在這條指令上，不再各開一條。
- `force`（兵力）：`1`＝精簡，`3`＝加倍；其他值（含 `2`）＝標準＝跟沒送一樣。
  - 精簡：起手留一半左右。32×32（萊伊、村莊）每方 坦克 2＋觀測員 1；64、96 每方 中坦克 3＋輕坦克 1＋重坦克 1＋榴彈砲 1＋觀測員 1。
  - 加倍：標準那一批原地不動，再加同樣的一批，每台往自己角落的方向斜移一格；那一格被建築、泥灘、植被或別的單位佔住時，由近到遠找第一個空格（順序固定）。32×32 每方 10 台，64、96 每方 30 台。
  - 精簡、加倍都把起手單位整批重排：我方 id 在前、敵方在後（跟 R043 大地圖的排法一樣）。標準不重排，id 照舊。
  - 只用到每張圖標準起手本來就有的兵種，不會繞過 R021–R023、R044 那些兵種閥。
- `income`（補給速度）：`1`＝慢（每 40 步 +1，標準的一半），`3`＝快（每 10 步 +1，標準的兩倍）；其他值＝標準（每 20 步 +1）。雙方一樣，電腦對手用同一套補給，不另外加成。
- 兩個欄位都是標準值時，這條指令不留下任何狀態：世界雜湊跟沒送逐位相同。

### 2. 開始選單（接著 R069 的 `src/ui/startMenu.ts` 做）

- 地圖那一列多一顆「村莊 32×32」：`createWorld` 原本的亂數村莊（地圖編號 0），道路位置、房子每個種子都不一樣。以前只有 `?noR026=1` 才看得到。R026 閥開著才多這一顆（閥關時「萊伊」那一格本來就是村莊）。
- 多一顆「遭遇戰設定」鍵，鍵上寫著現在的兵力、補給、種子。一般對戰與喪屍防守都有；沙盒沒有（沙盒自己放兵、沒有補給）；開戰後的暫停選單沒有（開打了不能改）。
- 按下去，選單換成設定頁：
  - 兵力：精簡／標準／加倍
  - 補給速度：慢／標準／快
  - 種子：一格可以打字的數字（0–4294967295），旁邊一顆「隨機」
  - 「完成」回到上一頁；設定頁上按 Esc 也是回上一頁
- 每改一項，後面的戰場當場重開成新的設定（跟 R069 選地圖一樣），回到布陣第 0 步。
- 「重新開始」「再來一局」沿用現在的設定與種子。

### 3. 網址（直接開局）

- `?force=1|2|3`、`?supply=1|2|3`、`?map=village`，加上本來就有的 `?seed=`、`?map=64|96`、`?mode=zombies`、`?ai=`。
- 帶 `noR069=1`（守衛預設）時不經選單，直接用這些設定進布陣。不帶時選單照樣出現，網址的值當選單的初始值。
- 不合法的值當標準，不報錯。

### 4. 接線與守衛

- 新檔 `src/sim/rules.ts`（模擬）、`src/ui/skirmish.ts`（設定的狀態、讀網址、產生 `rules` 指令）。`src/valves.ts` 加 `r046` 一行。
- `src/main.ts`：`seed` 從 `const` 改 `let`；`reset()` 加兩行（套規則、把指令記進紀錄）；選單接線那一行加幾個欄位。行數不超過 `tools/hub-budget.json` 的 673，上限不動。
- `reset()` 是兩支守衛（`tests/bombard-eligibility.mjs`、`tests/vegetation-view.mjs`）抽出來在沙箱裡跑的：它們的假環境補一個 `skirmish: undefined`，斷言不動。
- R069 的三支選單守衛改成帶 `noR046=1` 開頁（它們驗的是 R069 的選單，鍵的清單寫死），斷言一句不改。
- 新守衛：
  - `tests/skirmish.mjs`（不開瀏覽器：模擬規則、決定性、舊局不變、選單內容、讀網址、接線）
  - `tests/skirmish-browser.mjs`（真 Chrome：手機觸控＋故意弄壞）
  - `tests/skirmish-desktop-browser.mjs`（真 Chrome：桌機滑鼠與鍵盤、網址直接開局、預算）

## 驗收（動手前寫）

**模擬**

1. `rules` 只在第 0 步、沒有指揮部、沒有喪屍、不是沙盒時生效，只生效一次；第 1 步以後送、送第二次、先送 `eco` 再送，世界都不變。
2. `force` 是 1、3 以外的值，`income` 是 1、3 以外的值（含 2、0、負數、小數、字串、沒給）：世界雜湊跟沒送這條指令逐位相同。
3. 兵力，三種邊長（32：萊伊與村莊各驗；64；96）：
   - 精簡每方 3／7／7 台，加倍每方 10／30／30 台；雙方每個兵種的數量相同；
   - 加倍時，標準那一批每一台的位置與兵種都跟標準開局一樣；
   - 沒有單位站在建築、泥灘、植被上，沒有兩台在同一格，全部在地圖內；
   - 我方 id 全部小於敵方 id，id 從 1 連號。
   - 村莊用種子 0–199 全部驗一遍。
4. 補給速度：開了 `eco` 之後跑 400 步，我方補給增加量——慢 10、標準 20、快 40（敵方相同）。
5. 決定性：帶 `rules` 的一局（布陣、補給、電腦對手都開）跑 600 步——
   - 同種子同紀錄跑兩次雜湊相同；
   - 紀錄經 JSON 來回後重播雜湊相同；
   - 300 步時 `structuredClone` 再各自跑完，雜湊相同；
   - 先對世界直接套地圖與規則、再走 `step()`（遊戲裡布陣預覽的路徑），等於只走 `step()`（重播的路徑）。
6. 喪屍模式加兵力設定：敵方起手全部移除（照 R045），我方照設定的數量；先規則後喪屍的順序不因紀錄裡兩條指令誰先誰後而變。
7. 舊局不變：`tools/golden.json` 的 `eea1d59b` 不變；模擬守衛故意弄壞兩次（兵力不重排、補給速度不看規則），第一個紅燈各落在 `tests/skirmish.mjs` 自己的斷言上。

**選單與網址（真 Chrome）**

8. 閥開、開頁：開始選單有「遭遇戰設定」鍵與「村莊」；按進去看得到兵力三顆、補給速度三顆、種子輸入、隨機、完成，預設標準、標準、網址的種子（沒給是 1944）。沙盒模式沒有這顆鍵；開戰後的暫停選單沒有這顆鍵。
9. 套用：選加倍、快、打一個種子、選村莊之後——後面的世界當場換（單位數、地圖編號 0、種子都對），停在布陣第 0 步；紀錄第 0 步有對應的 `map` 與 `rules`；按「開始」→「開戰」跑 200 步後，世界雜湊等於拿這一局的紀錄從頭重播的雜湊。「隨機」會換一個種子，世界跟著換。
10. 網址直接開局：`?map=village&seed=7&force=3&supply=3`（守衛預設不經選單）進布陣後，世界雜湊等於從選單選出同樣設定的世界雜湊；`?force=9&supply=x` 等於標準。
11. 版面：1280×800、1440×900、412×915、390×844、360×780、860×412 六個尺寸，開始選單與設定頁的每顆鍵（含種子輸入）至少 44×44、整顆在畫面裡、中心點得到；「開始」與「完成」不用捲動就看得到。
12. 預算：412×860 加倍兵力開局（萊伊、鄉間、河鎮各一次）繪製呼叫 ≤ 20、三角形 ≤ 80,000；數字寫進驗收結果。
13. 逃生閥 `?noR046=1`：開始選單的鍵跟 R069 那一版完全一樣（沒有「遭遇戰設定」、沒有「村莊」）；`?force=`、`?supply=`、`?map=village` 不生效；但把一份帶 `rules` 的紀錄拿來重播，雜湊跟閥開時相同（閥只關入口，不關模擬）。
14. 故意弄壞至少三處（只編進 broken 那一份）：選了兵力不套用、選了補給速度不套用、閥關不掉，各紅在自己的斷言上。
15. R069 的三支選單守衛帶 `noR046=1` 後照舊全綠，斷言沒有改；`main.ts` 行數不超過 673；全套 CI 綠。附桌機與手機的設定頁樣張。
