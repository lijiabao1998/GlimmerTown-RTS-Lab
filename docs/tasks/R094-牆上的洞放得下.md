## 為什麼做這張

R088 合併後到公開站驗收：萊伊開戰，我方坦克打最近的一棟住宅，打到 T3（耐久 160／210）時整鎮只比 `?noR088=1` 多 8 個三角形——只有屋頂缺口（6）與一扇打破的窗（2），**牆上沒有洞、也沒有裂縫**。回頭在 Node 量：T2 時 211 棟住宅有 129 棟沒有洞，164 棟小屋、33 棟穀倉一棟都沒有。R088 卡面寫的「住宅、小屋、教堂每一棟都放得下」是錯的（那次數的時候把貼在玻璃上的「打破的窗」也算成洞了）。

原因：R088 找位置時，把**貼在牆上的所有東西**都當成不能壓的——窗、門以外，還有簷帶、勒腳、轉角石、木構、掛瓦、穀倉的木板。小的牆面上幾乎沒有一塊空的。卡面原本要的只是「不壓門窗」。

## 做什麼

1. 洞（與裂縫）只避開**窗**（玻璃與它周圍貼著的框、窗台）與**門**（從地面起、高過 0.2、寬不到 0.6 的貼牆的東西）；簷帶、勒腳、掛瓦、木板、木構的橫梁可以壓。
2. 洞口離牆面 0.02 → 0.035（崩掉的邊 0.037、裂縫 0.036）：在大部分貼牆的細節前面，不跟它們疊在同一個面上閃。
3. R088 卡面「沒做成的事」與施工紀錄裡那句錯的照實更正（寫明是 R094 查到、R094 修的）。

## 不改什麼

- 只改 `src/render/wearArt.ts` 找位置的規矩與洞的離牆距離；段、塌一角、塌一半、快取、殘影、彈痕都不動。
- 滿耐久（T0）逐位一樣；`?noR088=1` 逐位一樣（R088 的凍結指紋照過）。
- `src/sim` 不動；黃金雜湊 `eea1d59b`。
- 守衛：`tests/wear-art.mjs` 裡洞的離牆距離（0.02 → 0.035）與「洞不壓門窗」那一條的門窗定義跟著改（理由同上）；其他既有守衛不改。

## 驗收（動手前寫）

1. **卡面先**：第一個提交只有這張卡；`git diff 7bc015f -- src/sim` 是空的。
2. **放得下**：五張地圖、種子 1944、`more` 開著，T2 時：住宅、小屋、商店、穀倉、2×2 以上的教堂，**每一種至少八成**的建築牆上有洞（離牆 0.035 的洞口）；數字寫在卡面。
3. **不壓門窗**：每一個洞都不壓到同一面的玻璃（向外 0.03）與門（照上面的定義），在牆面範圍裡、牆頂以下。
4. **其他照舊**：`tests/wear-art.mjs` 全部的群組（段、T0、閥、快取、純函式、幾何、殘影、彈痕、效果、重建時間、接線）綠；每棟多的三角形仍 ≤ 64。
5. **故意弄壞**：至少 3 處（門不擋、窗不擋、洞貼回 0.02），各紅在指定的斷言上；`tests/wear-art-negative.mjs` 原有的 22 處照樣全紅在原本的斷言上。
6. **Chrome**：`tests/wear-art-browser.mjs`、`tests/wear-art-fire-browser.mjs` 綠；萊伊那一棟（公開站驗收的那一棟）打到 T3 時，整鎮比 `?noR088=1` 多的三角形 > 8（有洞）。
7. **收尾**：卡面、LOG、路線圖；R088 的合併資訊補進它的卡面、LOG、路線圖；`npm run check` 與 CI 綠。
