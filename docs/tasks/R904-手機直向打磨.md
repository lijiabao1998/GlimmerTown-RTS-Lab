# R904 手機直向打磨（R901 後續）

<!-- card: sim=no; golden=無; valve=?noR901=1; owner_ok= -->

## 為什麼做

R901 把直向手機的上方按鈕和建造／生產列做成可收合，但 412 寬直向仍有四件事不好用：底下單位列折成兩行、狀態列文字太密會換行、框選開著時長按不再下指令、收合後布陣前的入口列還留在畫面上。

## 做什麼

- 只在 `@media (max-width: 480px) and (orientation: portrait)`：生產列與布陣列的按鈕行改成單行橫向捲動，按鈕仍至少 44px；狀態列 `#hint` 單行，超出用省略號。
- 框選（框）開著時，手指停住 500 毫秒仍走既有長按砲擊；移動超過 8 CSS 像素才改成框選。關著時單指拖曳仍是平移。
- 具或產收合時，沙盒入口、地圖、喪屍、河鎮這幾顆布陣前的鍵也收掉。`?noR901=1` 與寬視窗不套這些規則。

## 不改什麼

不改 `src/sim`、`src/ui/tutorial.ts`、`src/render/post.ts`、`src/sim/ai.ts`、`tools/`、黃金雜湊 `eea1d59b`、相機數學、`main.ts`、`src/render/battle.ts`。不加 npm 套件、不加新閥。

## 驗收（動手前寫）

1. 412×915、390×915、360×915 直向：可見的生產列按鈕在同一行，狀態列高度不超過一行。360 與 390 同樣不折行。
2. 框選開著時，單指靜止長按仍打開砲擊選單，點一顆選單鍵只發一條既有 `fireAt`；同一狀態下拖曳超過 8 CSS 像素仍框選、不平移、不下令。
3. 具或產收合後，`#sb-enter`、`#map-pick`、`#zombies-pick`、`#town-pick` 不再顯示；展開後回到原本可見的那些。`?noR901=1` 不套收合。
4. 黃金雜湊仍是 `eea1d59b`。`main.ts` 與 `src/render/battle.ts` 行數不高過現有上限，本卡不改這兩個檔。DOM 不增加繪製呼叫。
